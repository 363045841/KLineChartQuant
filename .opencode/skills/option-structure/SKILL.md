# 期权结构与波动解读

数据由 NAS 采集器每分钟写入 `options/aggregate/<标的>/`，本机 8093 只读服务对外提供。
Agent 只用两个工具取数：`option_snapshot`（当前结构）与 `option_volatility_query`（长窗口分位），
不直接读文件、不自己算指标。

## 覆盖范围

| 标的 | 场所 | 可用到期 |
| --- | --- | --- |
| BTC、ETH | Deribit | 8 个，最远 90 天 |
| SOL、BNB、XRP | Binance | 2–5 个，最远约 10.6 天，持仓比 BTC/ETH 小两到三个数量级 |

ADA 等其余品种没有期权场所。查不到就直说「没有期权数据」，不要用别的品种顶替，也不要估。

## 第一步：取数

- 结构：`option_snapshot({ currency })`；省略 currency 时按图表品种映射（`BTCUSDT.P` → `BTC`）。
- 长窗口：`option_volatility_query({ currency, windows })`；默认 30 / 90 / 365 天。

## 第二步：校验

1. 采集时刻超过 10 分钟未更新 → 先说「数据滞后」，不要当实时。
2. 近月 DTE < 1 → IV 与墙位在交割前失效；换月后分位样本口径已变。
3. 场所：Deribit 与 Binance 的 IV 水平不可混用；面板标题与工具报告都带场所。
4. 样本天数：分位必须带窗口与样本天数；不足 5 天写「仅 N 天，分位不可用」。

## 第三步：结构三段

1. **翻转位**：现价在上方 = 正 Gamma（对冲压制波动）；在下方 = 负 Gamma（对冲放大波动）。
2. **两侧墙**：Γ 加权墙 = 日内对冲火力（主口径）；OI 墙 = 仓位聚集。两者错位时要明说错位，不要合并成一个价位。
3. **最大痛点**：到期赔付最小的行权价，是磁吸参考，不保证。

净 GEX 只做量级参考：符号依赖「call 记正、put 记负」的假设，不是真实承接。

## 第四步：波动四项

1. **IV Rank 与 IV Percentile 同时给**，各带窗口与样本天数。
2. **RV20**：日收盘算的年化已实现波动；不足 21 个收盘时为不可用。
3. **VRP** = 最新 ATM IV − RV20；正值表示隐含贵于已实现。
4. **期限结构与 25Δ 风险逆转**：偏斜必须带到期日（取 7–90 天里最接近 30 天的到期，alt 会落到 10.5 天）；负值 = 下行保护更贵。期限结构要看近高远低还是近低远高。

## 第五步：输出

- 一句基调 + 三段结构 + 四项波动，每项都引用工具返回的具体数字。
- 只用返回的数字，不自行推算未返回的指标；缺失就写不可用的原因。
- 不给入场、止损、目标价；用「更容易」「倾向于」这类条件句。
- 低分位不等于低风险：分位是当前 IV 在窗口中的位置，不是方向判断。
- 墙是观察锚点，不是支撑阻力结论；翻转位只描述对冲行为。
