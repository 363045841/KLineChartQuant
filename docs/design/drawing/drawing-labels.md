# 绘图附属文本与标签

## 背景

线和面积绘图需要展示用户输入的说明文字。文字必须随所属绘图的可见性、移动、删除和复制一起变化，不能成为独立绘图对象。组合图形（例如斐波那契回撤）由多条线组成，每条线需要独立的文本。

## 持久化形状

文字持久化在所属 `DrawingObject.labels.line` 与 `labels.area`，键为定义输出的线段或填充区域序号，值为 `{ text, position }`。`position` 为 `start`、`center` 或 `end`，表示所属线段的语义起点、中点和终点，不使用会随绘制方向改变含义的屏幕 `left/right`。帧投影按图元定义的输出顺序，将每条文本附着到对应 `LinePrimitive` 或 `AreaPrimitive`；斐波那契回撤的每根水平线因此可独立拥有文本。

线文本锚定在原始两点的起点、中点或终点，沿当前屏幕线段的上侧法线偏移。起点使用左对齐，从锚点右侧展开；终点使用右对齐，从锚点左侧展开，避免覆盖锚点。旋转角度由当前屏幕斜率实时计算并规范到可读方向，因此缩放、拖动、延长线和视口裁剪不会污染持久化模型。

## 键不变式归领域

「标签以渲染输出的线段 / 区域序号为键」这条不变式由领域类型与领域运行时表达，Agent 工具 schema 只是跟随者。

### 类型表达

```ts
/** 绘图标签的键：图元定义输出的线段或填充区域序号。 */
export type DrawingLabelIndex = `${number}`

export type DrawingLabels = {
  line: Record<DrawingLabelIndex, DrawingLabel>
  area: Record<DrawingLabelIndex, DrawingLabel>
}
```

对象字面量层面能挡住扁平形状与具名键；``Record<`${number}`, T>`` 与 `Record<string, T>` 互相可赋值，因此投影边界（Agent 快照等）不受连锁影响。

键的判定规则为 `^(0|[1-9]\d*)$`：合法键就是 `String(非负整数)`，排除 `-1`、`1.5`、`01`（前导零）、`position` 等渲染端不会产生的写法。

### 运行时归一化

所有入口（创建 / 更新 / 写入 / 整份替换）共用一个归一化函数：只保留序号键，且值必须是形状完整的标签对象，否则丢弃；换行统一为字面量控制码。

选「丢弃」而非「抛错」的理由：序号以外的键在渲染端本就按序号查找、取不到，丢弃是唯一有意义的解释；对导入/持久化数据抛严苛错误会把链路变脆，违反仓库「不使用严苛校验」的约定。Agent 侧仍由工具 schema 拒绝并给出可修正反馈，两者职责不重叠。

归一化函数接收 `unknown`（它本就是解析不可信输入的边界），因此可以类型安全地用畸形值直接测试，无需 `as`。

### 消费端构造键

消费端改用 `drawingLabelIndexKey(index)` 构造序号键，替代 `String(index)`。这样类型系统能保证索引来自真实序号，而不是任意字符串。

### 工具 schema 跟随领域

Agent 工具参数的序号正则从 `DRAWING_LABEL_INDEX_PATTERN` 派生，与领域判定同源，避免再次分叉。

## 换行规范

绘图文档的 `DrawingLabel.text` 使用字面量 `\n` 作为唯一持久化换行控制码。

- 用户在编辑器按 Enter 后，`DrawingDocument` 将 LF 或 CRLF 规范化为 `\n`。
- Agent 工具和导入数据直接使用 `\n`。
- `DrawingDocument` 是唯一的规范化边界，创建、更新和整份替换都经过它。
- 渲染前只将 `\n` 拆成逻辑行；不保存真实换行符。

渲染器只按 `\n` 拆分逻辑行，不以图元尺寸、视口尺寸或字符宽度自动折行。文本的行数和每行内容完全由用户或 Agent 输入的 `\n` 决定。线和箭头标签仍保持其旋转和语义位置；区域、点和独立文本按其既有锚点绘制。文本不限制行数，也不截断。

## 渲染与交互

绘图 Renderer 由宿主线图元直接绘制附属文本，不再将文本展开为独立 `TextPrimitive`。面积图元的文字在填充完成后以完整不透明度绘制，保证位于填充带上层。本设计不增加 Scene layer、RendererPlugin 或 GPU 文本管线。

用户将指针移入一条线或填充区域的当前标签热点时，Vue 宿主显示低对比度“+ 添加文本”提示；已有文本时显示当前文本。点击提示直接在该位置进入就地编辑，并选择起点、居中或终点；失焦或回车通过 `updateDrawing` 原子替换完整 `labels` 快照；提交空文本时从该快照删除对应条目。文字不是独立绘图对象，选中、拖拽和删除始终作用于所属绘图。

### 标签热点锚点

线段文本的绘制锚点与命中热点锚点必须来自同一布局函数 `resolveLineLabelLayout`（`packages/core/src/engine/drawing/geometry/impl/labelLayout.ts`）：语义位置（`start`/`center`/`end`）沿当前屏幕线段的**上侧法线偏移 `LINE_LABEL_NORMAL_OFFSET`（6px）**。

热点除锚点外还携带绘制使用的水平对齐、基线与字号，宿主输入框据此摆放：锚点贴文本块的对应边（线段/箭头基线为 `bottom`，锚点即文本块底边；填充区域为 `middle`，锚点即文本块中心），并以同一锚点旋转。因此输入框与已绘制文字重合，不再压在线上阻塞线段本身的点选与拖拽。

热点半径（18px）大于偏移量，悬停线段本身仍可触发；指针进入输入框后不再重算命中，提示不会中途消失。填充区域的锚点仍是其包围盒中心。

## 边界

- 持久化形状不变：仍是 `Record`，键仍是数字字符串，不改为数组，避免破坏已有文档。
- 不改「日内周期下日期命中多根 bar」这类行为问题。
- `DRAWING_KIND_VALUES` 用 `satisfies ReadonlyArray<DrawingKind>` 绑到领域联合，避免枚举漂移。
