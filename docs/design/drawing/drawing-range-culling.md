# 绘图按可见区间裁剪

## 问题与决策

帧投影原先对 Pane 内全部图元无条件执行 `compute()`，视口外的锚点还会被线性外推到屏幕外，只能靠 canvas 裁剪隐藏。全历史的脚本标签让滚动帧和重算帧的成本随图元总数线性增长。

现在每个 `DrawingDefinition` 声明图元在逻辑索引轴上的水平范围 `extent()`，`projectDrawingsForFrame` 在 `resolveDrawingForFrame` 之后、`compute()` 之前做区间相交判断；视口外图元不进入几何计算。

## 范围语义

- `start` / `end` 为逻辑索引，`end` 按闭区间参与相交判断；`null` 表示该侧无界。
- 无界图形必须由定义自己声明，投影层不按 kind 猜：水平线与十字线整轴可见，向右射线只有左边界，`extend: left/right/both` 的线与矩形对应一侧无界。
- 只做横向裁剪。纵向仍由价格轴与 canvas 负责，避免把价格范围不同的图元误裁。
- 可见区间两侧各多留一根 K 线，覆盖锚点外侧仍可能溢入视口的文字、线帽和端点。
- 时间锚点先解析为逻辑索引再判断；未来槽位同样按解析后的索引判断。
- 未注册的第三方定义无法判断范围，按整轴可见处理，宁可多画也不误裁。

## 不改变的东西

- 不改变图元存储额度与淘汰规则。裁剪只降低投影和绘制成本，不能恢复已被脚本引擎淘汰的图元。
- 不改变锚点解析、选择、命中与轴标签语义；选中图元同样按可见区间裁剪，视口外不会产生手柄或轴标签。

## 验证

`frameProjection.test.ts` 覆盖：区间内与两侧余量内的标签、跨区间的线段、完全在区间外的线段、视口外的垂直线、整轴可见的水平线、伸入视口的水平射线、从视口外向右延伸的矩形。
