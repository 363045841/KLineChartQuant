# 桌面工作区的提交与恢复

桌面宿主有两种持久化身份：主进程记录需要重新打开的工作区 ID，渲染进程记录每个工作区的标签。两者继续分别由文件和原有 IndexedDB 数据库保存，不复制图表状态。

## 窗口清单

主进程持有一个 `createWorkspaceSessionStore`。调用保存时捕获 ID 数组副本，文件写入与 rename 按调用顺序串行执行。保存失败返回给调用者，由主进程记录错误；后续提交可以继续。退出应用前等待队列结束，因此不会在后台文件写入尚未完成时销毁应用。

普通关闭窗口时更新剩余窗口；关闭最后一个窗口保留此前的单窗口清单。显式退出应用时，在销毁任何窗口之前冻结完整清单，后续 closed 事件不再逐个删除会话成员。这两条规则分别对应关闭最后一个窗口后重新启动，以及菜单退出后恢复多窗口。

## 标签提交

所有标签操作都在同一 object store 的读写事务中读取最新值并执行领域变更。组件不再安排整份缓存快照的延迟保存，也不在页面退出时补写旧快照。一次操作提交后才更新组件可见状态；因此可见的新标签已经有持久化记录。

跨窗口接管在一个事务内读取源和目标，再写入两边。目标写入失败会回滚源的删除，调用方不会提前更新目标内存或关闭源窗口。相同标签被两个窗口同时接管时，IndexedDB 的读写事务顺序保证只有一个操作能读到源标签。

源工作区搬空后保留 `{ tabs: [], activeTabId: '' }`，区别于不存在的记录。迟到的品种通知和排序操作会读取这个最新空集合，不会根据源窗口的旧缓存重新创建标签。本地初始化、变更、接管和重读也按调用顺序执行，防止异步结果倒序发布。

数据库名称、版本、object store、记录键和持久化范围均沿用原定义，无需迁移现有记录。事务完成后关闭数据库连接，不保留需要在销毁时刷新的存储缓存。

## 拖放输入

JSON 解析结果保持 `unknown`，只在确认非空对象、来源工作区与标签身份均为非空字符串后交给重排或接管。普通文本、`null`、数组和字段类型错误不会调用标签操作。

## 验证边界

文件测试使用真实临时目录；移交测试使用 fake-indexeddb 执行实际事务并注入目标写入失败；窗口测试仅替代 Electron 窗口能力，清单保存仍使用真实文件；拖放测试从 Vue 组件的 drop 事件进入。自动化验证不声称覆盖操作系统强制终止进程或断电。
