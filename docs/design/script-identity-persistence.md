# 脚本身份与持久化

脚本只有 builtin 和 user 两种身份，随注册表中的源码文档快照读取。
指标身份规范化保留 Unicode 字母与数字，使中文脚本名称及“副本”后缀保持独立身份。
内置源码在启动时从文件注册，不进入 IndexedDB，不允许修改或删除。
创建副本只生成独立名称的用户草稿，保存时与新建用户脚本走同一入口。

用户脚本通过 ScriptService 的异步 create/update/remove 写入现有 IndexedDB 持久化 API。
服务从唯一注册表派生用户源码列表，事务成功后才发布运行定义，不维护平行源码仓库。
启动先读取保存列表，重新编译并注册；保存仅包含源码和 revision，不保存编译产物。
同一服务串行提交，保留 revision 冲突检查，界面在提交期间禁止重复保存和编辑。

Core IndexedDB API 增加 strictLoad 选项：默认行为不变，脚本存储启用它以区分无记录和读取失败。
读取失败中止启动，避免将异常当成空列表后覆盖已有脚本。编辑器仅 user 身份允许输入，
弹窗与独立窗口复用同一工作区和会话，左侧工具栏及自定义脚本分类的入口均创建用户草稿。
