# K 线帧几何与屏幕投影

## 中心点优先

图表此前先计算 `kLinePositions` 左边界，再由左边界推导中心点。分时模式的折线、量柱和十字线需要同一条时间轴基准，左边界优先会让不同渲染器再次执行 `position + width / 2`，在 DPR 取整、奇偶宽度和午休时间槽缺口下产生不同结果。

`ChartRenderer` 以 `kLineCenters` 为一帧 X 几何的唯一基准，所有中心点均先在物理像素空间确定：

- K 线中心由交易序号、`unitPx` 和奇数 `kWidthPx` 计算。
- 分时中心由交易时段 slot 的固定整数物理像素网格计算。
- K 线实体、量柱矩形与兼容的 `kLinePositions` 都由中心点向左推导。
- 十字线的命中、吸附，以及折线、指标、标记和月份分界线直接使用 `kLineCenters`。

浏览器 `scroll` 事件必须先通过 viewport action 将 DOM `scrollLeft` 写入 StateKernel，再申请完整帧。指标异步计算状态不能阻止滚动帧；渲染器继续消费最近一次已提交的指标结果，待 Worker 返回后再由指标失效回调合并后续帧。

## 屏幕投影与物理像素

世界坐标投影到屏幕 X 坐标时执行 `(round(worldX * dpr) - round(scrollLeft * dpr)) / dpr`：世界坐标与滚动量**分别**对齐到物理像素后再相减。禁止对 `worldX - scrollLeft` 整体取整——那样每个点的舍入方向会随滚动变化，屏幕相位会抖动，几何缓存也会每帧失效。Canvas2D、交互投影与 GPU 后端遵循同一顺序。

K 线实体在世界坐标中按物理像素网格生成，但滚动偏移可能使其在屏幕坐标中再次落到半像素。`projectWorldRectToScreen` 是世界矩形 X 边界进入屏幕前的唯一 CPU 投影规则：左右边界分别吸附，再保证至少一个物理像素宽度。

- Canvas2D 与 WebGL 共用该函数；WebGPU 在 shader 内执行等价的顶点投影，因为该阶段必须在 GPU 执行。
- GPU 后端不得在顶点着色器中依赖大世界坐标与 `scrollLeft` 的减法精度。矩形实例在 CPU 双精度空间按统一投影规则转换为视口局部坐标后上传，shader 仅处理小坐标；顶点 shader 同时声明 `highp float`，确保仍使用世界坐标的折线在移动 GPU 上保持足够精度。
- 公共原语契约把横向偏移挂在图元上（`offsetX`），由后端在绘制时统一扣除；数据空间折线改由 `DataTransform` uniform 还原，滚动与轴缩放不重写顶点缓冲。
- `kWidthPx` 作为帧级可用实体宽度进入 `RenderGeometryContext`，仅用于蜡烛与 OHLC。Columns 消费横轴投影传入的 `slotGrid`，不读取蜡烛实体宽度或影线几何。

## 实体、量柱与影线宽度

K 线实体按影线粗细保持同奇偶，同一帧实体宽度一致；Columns 是时间槽位填充，不属于这套实体宽度规则。分时交易槽位布局独立使用 `floor(axisWidthPx / sessionSlots)` 作为固定 `unitPx`，多余像素均分到左右边距；物理宽度不足以容纳每槽一个像素时回退比例布局。

影线按缩放级别选择固定物理宽度：第 1–9 级为 1 个物理像素，第 10 级及以上为 2 个物理像素，不随 DPR 增粗。不按实体宽度渐进增长，也不超过粗档；缩小时切回细档。

- 实体宽度与影线保持相同物理像素奇偶性：不匹配时实体缩窄一个物理像素，实体至少与影线等宽。
- 细档在所有 DPR 下对应奇数宽，粗档在所有 DPR 下对应偶数宽。
- 两者共用对齐中心，偶数宽中心为整数物理像素、奇数宽中心为半整数物理像素；左右边界全部为整数物理像素。
- 此处仅调整绘制矩形，不改变槽位步长和指针缩放坐标。
- 实体和影线的位置、宽高、最小高度均在整数物理像素空间计算，最小实体高度为一个物理像素。
- 仅在向共享 Renderer/Canvas 接口输出矩形时按 DPR 换算坐标，Canvas、WebGL 和 WebGPU 消费同一组几何。
- 缩放级别加入主图和 Plot 的投影缓存输入，即使 `kWidthPx` 未变化，跨影线档位缩放也必须重新生成实体与影线几何。

## 实体间距

`kGapFromKWidth(kWidth, dpr, gapRatio)` 是 K 线与对比视图的唯一间距派生规则。

- 间距 = max(0, 实体宽度 × 密度系数)；不额外保留最小物理像素，系数来自 `settings.klineDensity`（紧凑 0.3 / 标准 0.6 / 宽松 0.9），映射只在图表设置中声明一处。
- 实体退化到 1 物理像素竖线时，间距按 0 处理；槽距仍随逻辑宽度连续变化，避免低档缩放时 level 更新但画面不动。像素奇偶校正造成的残余空隙不视为间距配置。
- 槽距 `unitPx` 必须保留小数，不按物理像素取整：取整会让缩放动画退化成逐像素跳格。
- 连续槽距投影到整数像素后，相邻中心距离可能相差 1 物理像素；这是蜡烛的像素对齐行为，不作为 Columns 的间隙规则。实际蜡烛空隙还包含逻辑宽度与最终实体宽度的校正差值。
- 密度只改槽距，不参与实体与影线的奇偶校正；实体宽度仍由缩放级别派生。
- 密度经 `ChartStateKernel` 的视口几何输入投影进入 `ScaleXInput`，横向标尺策略用派生间距生成槽位网格；渲染、交互和指针缩放共用该投影。
- 切换密度会改变槽距，但**不做滚动锚点补偿**：世界滚动量保持不变，可见 K 线允许一次性横向重排。不要为设置变更另加补偿路径，缩放锚点仍只由 `ChartZoomController` 负责。
- 间距改变时，缩放仍优先保持鼠标连续槽位，仅在可见数据边界处修正视口。

## Columns 的槽位填充

- 横轴 `ScaleXSnapshot.grid` 通过 `RenderGeometryContext.slotGrid` 传入，不从蜡烛渲染结果反推槽距或柱宽。
- 第 i 根柱占据 `[i - 0.5, i + 0.5]` 的时间槽位。每次重放先扣除当前滚动量，再对左右槽界进行物理像素对齐；相邻槽位使用完全相同的公共边界。
- 对齐后的槽界左右各内缩 1 个物理像素，相邻有效柱之间固定留下 2 个物理像素。小数槽宽产生的像素余量由柱宽吸收，不要求 Columns 宽度为奇数或跟随影线粗细。
- 1–2 个物理像素的窄槽取消留白；不足一个物理像素的槽位不绘制，防止负宽或跨槽覆盖。
- 槽界在屏幕投影阶段每帧计算，不能缓存已经取整的柱宽再按滚动平移，否则小数槽距仍会把误差重新引入空隙。
- `size` 不控制 Columns 宽度。Histogram 继续使用固定像素宽度，主图蜡烛、密度派生和连续缩放规则保持独立。

## 分时与副图

分时模式不会自动创建成交量或其他指标副图。用户已启用且声明支持分时的指标持续使用原实例、pane 和布局配置；量柱在用户启用 VOL 时与 K 线模式共用同一 renderer。

副图实例将 `instanceId`、`paneId`、canonical `indicatorId` 和 `ordinal` 分开保存。`instanceId` 供添加、更新和删除 API 使用；`paneId` 只供布局、渲染器和 StateStore 绑定使用；`indicatorId` 只表达指标能力；`ordinal` 只供显示或排序。新增副图分别生成 UUID 实例和 pane 身份，禁止再通过拼接指标名称和编号推断任何业务语义。

## 兼容性与范围

`RenderContext.kLinePositions` 继续保留，供绘图等旧接口读取，但它是派生数据，不再作为中心点的来源。K 线实体渲染直接消费 `kLineCenters`。

本组几何规则只统一 Candle 矩形的 X 投影与物理宽度来源；折线、绘图及标记沿用其已有的几何契约。
