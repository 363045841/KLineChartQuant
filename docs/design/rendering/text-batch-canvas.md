# 含文字批次由 Canvas 单次重放

## 症状

同一张图在 WebGL2 / WebGPU 后端下，含文字标签的图层（绘图标签、Box / Label 指标图元、带文字的标记）出现严重性能回归，Canvas 后端正常。回归与文字数量近似线性，文字越多越慢，而几何数量不变。

## 根因

文字只由 Canvas 解释，GPU 后端无法把文字排进自己的有序几何批次。旧实现为保留图文交错顺序，在每一段文字处切段：先把该段之前的几何渲染到离屏目标，再整张合成到当前目标，然后在目标上画文字。每个切段都包含一次整张离屏渲染和一次整张 `drawImage`，一批 N 段文字就是 N 次离屏渲染加 N+1 次整画布拷贝；成本由文字数量决定，而不是由覆盖面积或几何数量决定。Canvas 后端没有这一步，所以只有 GPU 后端回归。

## 决策

GPU 后端只接受纯几何批次：

- 批次中出现任何 `text` 原语时，整批交给 Canvas 单次重放，与 Canvas 后端同一路径、同一顺序、同一代价。
- 纯几何批次仍整批准备、一次离屏渲染、一次整张合成，`compositions` 每批最多为 1。
- 不再保留 staging 画布与按文字切段的合成逻辑。

整批重放天然满足原子性：Canvas 要么按顺序画完整批，要么在入口前就失败，不存在"前半批已上屏、后半批失败"的部分输出。图文交错顺序由同一次 Canvas 重放保证，不需要也不允许把所有文字挪到批次末尾来换取合批数。

## 边界

- 主图带（`background` / `primary` / `indicator` / `component`）的 `draw-list` 图层仍由 Scene 拆分：几何写入可见 GPU 表面，文字写入其上方的 2D 主画布。两者分属固定 DOM 层，相对顺序由层序决定；同一次提交的文字累积成一批交给合成器，保持文字之间的先后顺序。
- `drawing` / `overlay` 等 `context` 图层把图文一起提交，按本决策整批走 Canvas。
- 该规则不改变坐标轴、十字线、第三方 Canvas 插件与局部重绘策略。

## 验证

- `primitives/__tests__/gpu.test.ts`：含文字批次不创建设备、`compositions` 为 0，且矩形 → 文字 → 圆的绘制调用顺序不变；纯几何批次只有一次离屏渲染与一次合成。
- `bench/primitives.html`：三后端像素与计数回归，含文字批次的绘制顺序与 Canvas 一致。
- `bench/index.html`：同一张真实图表切换三后端，确认文字图层不再随文字数量放大整画布合成次数。
