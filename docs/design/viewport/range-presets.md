# 时间范围预置

## 决策

「1D / 7D / 1M / 3M / 6M / YTD / 1Y / 5Y / ALL」这类预置拆成两个独立能力，chip 只做编排：

- **数据池覆盖**：`ChartController.ensureCoverageFrom(fromTs): Promise<CoverageResult>`，`ChartDataManager` 内部翻页直到覆盖、耗尽或确认无法再向前扩。
- **视图定位**：`ChartController.frameTimeRange(from, to)` 与 `frameView(snapshot)`，由 `ChartZoomController.frame()` 一次提交档位与滚动。

预置本身不再携带周期：点击 chip 时由界面按窗口跨度挑选周期，再整体替换主品种（`setPrimaryMarket`）。

## 原因

此前的加载与定位各有多条路径：

- 补历史有「视口贴边预取」和「调用方逐页催」两套守卫，且都只取一页，循环被推给调用方。
- 复位、切品种恢复、滚轮缩放各自写缩放与滚动，彼此会覆盖。
- 缩放的公开入口只有离散档位，无法表达「把这个窗口装进屏幕」。

把触发、守卫、循环、提交各收敛成一处，预置与其它入口（拖选补历史、贴边界预取、首帧定位、布局恢复）共用同一套能力。

## 实现

- `engine/viewport/rangePreset.ts` 是纯函数模块：窗口解析、周期挑选、帧几何、高亮匹配与索引二分，不持有状态。
- 周期完全由窗口的**真实跨度**推导：`pickRangePeriod(supported, spanMs)` 在品种支持的周期里选「跨度 ÷ 周期长度 ≤ 可读根数」的最细一个，都放不下才用最粗的。没有预置到周期的映射表。
- `ALL` 的跨度来自数据本身：先用最粗支持周期把历史补到耗尽（`ensureCoverageFrom(-Infinity)`），得到完整跨度后按同一规则推导周期，再补到耗尽并框全部。
- 帧目标只有两个数：连续缩放档位与首槽位。槽距是唯一自由度，`step = 绘图宽 / (根数 + 未来槽位 + 0.5)`，再由 `step / (1 + 间距系数)` 反解 K 线宽度并线性映射到档位；放不下时按配置上下限截断。
- `ChartZoomController.frame()` 与交互缩放共用 `commitView`：档位与滚动在同一次 batch 提交，档位允许小数。档位未变化时仍然提交，因为定位本身会改变滚动。
- 覆盖循环是唯一的加载入口：同 buffer 的并发请求共享一次循环并收窄下界；序列切换、源耗尽、页无进展都会结束循环。`checkVisibleRangeGap` 与拖选补历史都只是它的调用方。
- 数据层不再读写视口：视口快照的保存与恢复移到 `Chart`，恢复走 `frameView`，快照以槽位偏移（`anchorOffsetSlots`）记录位置，不再保存像素偏移与几何换算。
- 高亮由真实可见窗口派生：右端停在最新一根，且窗口起点与预置起点相差不超过一根时命中。平移、缩放、手动改周期都会让高亮自动熄灭，不另存点击状态。

## 边界

- `ALL` 会补到数据源耗尽；跨度过大的源会在补全期间逐页加载。
- 周期挑选按自然时间跨度估算根数，交易时段市场会偏保守（选得更粗），不会出现蜡烛挤成条的情况。
- `YTD` 以图表显示时区（`displayTimeZone`）的 1 月 1 日为起点，与时间轴刻度同源；挑周期时使用它到最新一根的真实跨度。
- 分时与五日分时不适用预置，界面整排置灰。
