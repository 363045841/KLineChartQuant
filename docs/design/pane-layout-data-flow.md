# Pane 配置与异步指标内容的数据流

## 问题

旧链路从指标目录推导实例位置，再从已经就绪的实例过滤 pane。脚本启动逐个发布定义，
于是恢复布局逐个增长；ResizeObserver 触发的像素布局又反向提交规格和比例，覆盖尚未就绪
的 pane。新增副图还会重置所有窗格的默认权重。等待脚本初始化仅隐藏了这些状态耦合。

## 状态边界

- 布局文档保存指标实例的 role、paneId、参数，以及完整 paneSpecs 顺序和高度权重。
- paneSpecs.ratio 是高度权重的唯一来源；paneRatios 只是只读派生接口，不再重复持久化。
- PaneState 独立于指标注册表。恢复配置即恢复全部 pane，即使指标尚未加载或加载失败。
- IndicatorState 保存全部实例配置，不因目录尚未发布而隐藏实例。
- 指标管理器只将已注册的定义送入计算与 Layer 投影；就绪后补充内容，不创建或调整 pane。
- LayoutManager 先原子发布文档配置，再调用内容加载入口；布局恢复不等待原生指标模块下载。
- 定义发布把执行器安装和目录通知放在同一 batch 中，响应式投影不会先于执行器准备完成。

## 写入方向

```text
IndexedDB 布局文档 → Kernel 用户配置 → Pane DOM 与像素布局
脚本读取 / 编译 / 注册 → 就绪定义 → 计算与 Layer → 填入已有 pane
用户增删 / 拖拽 / 排序 → PaneManager / 边界拖动命令 → 配置 → 自动保存
```

容器尺寸、DPR、最小高度约束只影响本次像素投影，不得写回用户比例。用户拖动边界时，
才把实际像素分配转换为新的配置权重。新增 pane 按默认份额分配空间，但保留已有 pane
之间的比例。脚本显式修改主副图位置属于用户内容变更，由领域命令原子迁移实例归属和
pane 配置，不能靠目录重算悄悄改变布局；两个数据视图工作区一起处理。

## 持久化

Alpha 布局文档和布局数据库版本提升到 3。不读取旧版布局文档，不迁移 layoutId 或重复的
paneRatios。旧归档中的文档被当前版本校验剔除，首次加载建立新的默认布局。脚本源码、
行情缓存、Agent 与其他独立数据库不需要改变。

## 验证

恢复尚未注册的多个指标时，首次 pane 顺序、比例和轴偏好即完整。逐个注册定义只能改变
内容；容器缩小再放大、DPR 改变与重绘均不得改变配置或持久化快照。另验证新增 pane、
边界拖动、主副图迁移、工作区切换及新版本 IndexedDB 的保存和重载。
