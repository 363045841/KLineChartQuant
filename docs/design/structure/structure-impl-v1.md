## 1. 枢轴：严格极值 + 固定确认延迟

定义：`high[i]` 若严格大于 `[i-k, i+k]` 内其它所有 high，则 `i` 是一个高点枢轴，`confirmedBarIndex = i + k`。

三个刻意选择：

1. **严格不等号（`>` / `<`）**：平顶、平底不产枢轴。宁可少认一个摆动点，也不要把平台整理里的抖动当成结构。
2. **确认延迟固定为 k**：确认该枢轴恰好需要之后 k 根 bar，因此 `confirmedBarIndex = barIndex + lookback`，
   与契约的 `confirmedBarIndex >= barIndex` 一致，且不会出现「同一枢轴在不同时刻给出不同值」。
3. **不重绘**：单测 `pivots.test.ts` 对 60 根序列逐个前缀验证——前缀算出的枢轴集合，
   恒等于全量结果里 `confirmedBarIndex <= 前缀末尾` 的子集。这是对 `SMC #101`（居中窗口把 PF 吹到 7.32）的防御性验证。

## 2. BOS / CHoCH：收盘确认，不依赖未来摆动点

- `barIndex` = 收盘价越过枢轴价的那根 bar，`confirmedBarIndex === barIndex`。影线穿越不算。
  与 `SMC #114` 的差别就在这：它的破位要等事件之后的摆动点确认，实际晚 11 根才可知；这里当根收盘即确认。
- 只使用 `confirmedBarIndex <= 当前 bar` 的枢轴，未确认的枢轴不参与判定（单测覆盖）。
- 一次破位会**吃掉同侧所有已被越过的枢轴**（同一波推进里被依次突破的结构），只对「被越过枢轴中价格最高的那条」记一条事件。
- 归类：趋势由最近一次破位方向定义；同向记 BOS，反向记 CHoCH；首次破位之前趋势未定，记 CHoCH。
- `marginRatio` 的分母是被突破枢轴到最近一个反向枢轴的距离；没有反向枢轴时记 0（无从归一，不用假的比值）。

**性能护栏**：每根 bar 只比较「最低未破高点 / 最高未破低点」两个标量，只有收盘越过它们才做线性扫描；
每个枢轴最多被吃掉一次。这样 8 万根 bar 的检测是 O(bars + pivots)，不会退化成 O(bars × pivots)。

## 3. 结构位止损

`packages/backtest/src/impl/stop.ts` 把止损来源抽成 `StopResolver`：

- `cloud`：多头取云下沿、空头取云上沿（旧口径）。
- `structure`：多头取**最近一个已确认且低于入场价**的摆动低点，空头反之；
  二分定位 `confirmedBarIndex <= 信号 bar` 的最后一条，再向前找价格在正确一侧的那条。
- 找不到可用枢轴时返回 `null`，回放把它记为「无止损位」并**不开仓**——不得静默退回云边，
  否则两种口径的结果无法归因。

随机入场基准走同一个 `StopResolver`，保证基准与策略用同一套止损规则与同一道距离闸门。

## 7. 止损是不是被噪声扫掉的（2026-11-10）

对 LTF+1D 那 1,181 笔里的 534 笔打损单做两项反事实统计：

| 指标 | BTC | ETH |
| --- | ---: | ---: |
| 打损后 24 根内继续逆行（R 中位） | +0.90R | +0.79R |
| 打损后回到入场价的比例 | 35.9% | 38.3% |
| 放宽止损到 1.5R（目标价不变）能到 2R 的打损单 | 8.1% | 17.4% |
| 放宽止损到 2.0R（目标价不变）能到 2R 的打损单 | 18.5% | 30.3% |

**结论：打损主要不是被扫，是方向本来就错。** 打损之后价格平均还要再逆行约 0.9R，且三分之二不回入场价；把止损放宽一倍，能救回的打损单只有 8%–30%，却要在 100% 的交易上多承担风险。在这套入场规则下，「止损太紧」不是主要矛盾。

## 8. 关于「入场后调用 LLM 动态调整止损止盈」的评估（未采纳）

结论：**不放进数值判定链**。四条理由按硬度排序：

1. **不可复现 ⇒ 回测失效**。同一信号两次调用会给出不同止损，walk-forward、参数优化、A/B 归因全部无法进行。
   这与地图已定案的两条硬约束直接冲突：#5「回测必须复用线上同一套规则」、#10「LLM 不参与任何数值判定，只在可选解说层」。
2. **效应量太小**。当前最好配置合计 +0.020R、单笔 R 标准差约 1.3；LLM 每次调整的方差远大于这个效应量，
   无法区分「模型判断更好」与「这次采样走运」。
3. **成本与迭代速度**。每改一次参数就要重跑全历史（2,694 个信号 × 1 次调用），而不可复现的重跑之间无法比较。
4. **它解决的不是实测暴露的问题**。§7 已证明打损主要来自方向错误，不是止损位偏差。

替代方案（确定性的，可回测，同样能实现「不机械」）：

- **目标改成结构位**：下一个反向枢轴 / 前高前低 / 期权墙，而不是固定 2R；加 min/max 边界防极端。
- **动态管理规则**：1R 保本、第一目标减半、结构追踪（用最近确认枢轴抬止损）、时间止损。
  这正是 #7 契约里已设计的 `managedOutcome` 双曲线，回测要同时记录 `theoreticalOutcome` 与 `managedOutcome`。
- **止损缓冲**：止损放在枢轴外 k × 通道高度处，避免正好挂在人人都看的价位上——这是「防扫单」的正确做法，
  但仍需回测验证是否值得。

LLM 的正确位置：解说层（解释「这里为什么打损」「这个结构意味着什么」），以及**离线研究**——
一次性让模型对历史信号给建议、冻结成 JSON 数据集当成一个策略变体参与对照；结论只对那批冻结数据成立，不得进线上判定。

## 9. 结构破位入场 + 力度剪枝（2026-11-10）

## 12. 周期外推与目标位（2026-11-11）

§10 留了三候选下一步：12h/1d 复现、forward 测试、目标价改结构位。本节用已有的 1h/4h 交易明细先把第一条证伪，再把第三条里的目标位参数真正量化。

### 12.1 拉长周期不能提显著性（解析结论）

用 1h 与 4h 实测反推周期指数 `k`（单笔期望 ∝ 周期^k）：全样本 `k = 0.438`、2022+ `k = 0.512`，都接近 `√T = 0.5`。而样本数与有效样本数都随周期反比下降（`N ∝ 1/T`、`Neff ∝ 1/T`）。两者相乘后，**t 值几乎不随周期变化**：

| 周期 | 全样本期望（外推） | 全样本 Neff | 全样本 t | 2022+ t |
| --- | ---: | ---: | ---: | ---: |
| 1h | 0.121 | 1,182 | 3.47 | 1.28 |
| 4h | 0.222 | 296 | 3.18 | 1.30 |
| 12h | 0.359 | 99 | 2.97 | 1.31 |
| 1d | 0.486 | 49 | 2.84 | 1.33 |
| 3d | 0.787 | 16 | 2.66 | 1.34 |

结论：**候选 A（12h/1d 复现）在数学上就不可能成功**——单笔效应量的增长被样本量的下降精确抵消。它只会产出更少、更不稳定的样本，不会把 t 推过 2。这条路线不必再跑。

一个反直觉的推论：**周期越短，全样本 t 越高**（1h 3.47 > 4h 3.18 > 1d 2.84）。样本量比单笔效应量更值钱。

### 12.2 ρ 的计算口径必须先钉死（否则结论差一个数量级）

`Neff = N / (1 + 5ρ)` 的分母完全取决于 ρ 怎么算。同两份数据、两种常见口径：

| 口径 | 1h 全样本 | 1h 2022+ | 4h 全样本 | 4h 2022+ |
| --- | ---: | ---: | ---: | ---: |
| 零填充（缺交易日记 0） | 0.105 | 0.124 | 0.056 | 0.075 |
| 仅共同交易日 | 0.408 | 0.423 | 0.457 | 0.454 |

零填充口径算出的 ρ 只有共同交易日口径的 1/5，Neff 会被放大到约 3 倍，t 随之虚高。**§9/§10 用的是「仅共同交易日」口径**，因为它度量的是「同一天两个币是否同向」，而不是「两个币交易日是否对齐」——后者引入的大量零值会把真实相关性稀释掉。本节的复核都用这一口径。

复核结果与 §10 方向一致（1h 全样本 ρ=0.408 vs 文档 0.325，t 3.39 vs 2.84，差异来自早前脚本对逐笔相关的近似）：**结论不因口径复核而改变**。

这套口径已固化成脚本，不再靠临时脚本现算：

```bash
# 2022+ / 5bp / Neff 校正，外加剔前 1% 赢单与日期块自举两项稳健性
node scripts/backtest-significance.mjs temp/backtest-4h/m0.2/trades.csv --cost-bps 5
# 等价写法
pnpm backtest:significance temp/backtest-4h/m0.2/trades.csv
```

### 12.3 2R 固定目标是瓶颈：3R 更好

`target1R` 此前硬编码为 2，无法从 CLI 调。本轮加了 `--target-r`（`target2R` 固定为 `target1R + 1`，它只记录是否到达、不参与结算），测试补 `settle` 的 3R 用例。

在「入场、止损、闸门全不变，只改目标倍数」下的重跑（六品种，表中为 5bp 净期望）：

| 口径 | 2R 期望 | 2R t | 3R 期望 | 3R t |
| --- | ---: | ---: | ---: | ---: |
| 4h 全样本 | +0.222 | 3.17 | **+0.292** | **3.50** |
| 4h 2022+ | +0.120 | 1.35 | **+0.193** | **1.78** |
| 1h 全样本 | +0.121 | 3.39 | **+0.164** | **3.75** |
| 1h 2022+ | +0.059 | 1.25 | **+0.086** | **1.50** |

稳健性（4h 2022+，5bp）：剔除最大 1% 赢单后 t 为 1.53（3R）vs 1.13（2R）；日期块自举 30 天块 t 为 1.59 vs 1.24。**3R 比 2R 在三种口径上都更好，且不是右尾依赖造成的**。

目标倍数继续放大到 4R 会回落（4h 2022+ 0.231R / t 1.87，剔 1% 后 1.58），最优区间在 3R。

### 12.4 保本规则几乎无效（并修正一次误判）

用 `max_favorable_r` 做的粗算会得出「1R 保本把 4h 2022+ t 从 1.35 抬到 2.19」，**这个算法是错的**：它只把「曾到 +1R 最终打损」的单改成 0R，却没有计入「因为止损上移到保本位、本来能到 2R 的单被提前打掉」。

逐 bar 因果模拟（止损上移只用已收盘信息，同一根 bar 内止损优先）的真实结果：

| 保本触发 | 4h 2022+ 期望 | t | 1h 2022+ 期望 | t |
| --- | ---: | ---: | ---: | ---: |
| 不保本（基线） | +0.120 | 1.35 | +0.059 | 1.25 |
| +0.5R 保本 | +0.129 | 1.66 | +0.046 | 1.11 |
| +1R 保本 | +0.124 | 1.45 | +0.061 | 1.36 |
| +1.5R 保本 | +0.119 | 1.34 | +0.059 | 1.26 |

结论：**保本规则最多把 t 抬 0.2–0.3，且只在 4h 上成立；1h 上 @0.5R 反而变差**。它不是一个能解决显著性的杠杆。`managedOutcome` 契约的价值在于贴合实盘执行，不在于提高统计功效。

### 12.5 取消目标（只止损）不稳

4h 2022+ 用「无目标、只等止损或 200 bar 到期」得到 +0.301R / t 1.77，看起来最好，但：

- 收益的 **89% 来自前 5% 的赢单**（2R 口径是 45%，3R 是 48%）；剔除最大 1% 赢单后 t 掉到 1.21。
- 1h 上同样口径 t 2.32 → 剔 1% 后 0.74。

这是典型的「少数肥尾撑起均值」形态，样本内好看、样本外会崩。**不采用**。

### 12.6 本轮结论

1. **候选 A（12h/1d）已被证伪**，不必再跑：周期外推的 t 恒定。
2. **目标位 3R 是一个真实、可复现的改进**：两个周期、2022+/全样本、三种稳健性口径全部变好，4h 2022+ 从 1.35 抬到 1.78（5bp）/1.65（10bp）。
3. **但 3R 仍未过 t=2 线**（最接近的 4h 2022+ 只有 1.78）。结合 §12.1，靠「换周期」或「单条管理规则」都过不了线。
4. 剩下的路只有两条：**纵向等新数据**（约 3 年，不可行）或 **横向找真正独立的样本**（新品种 / 新市场 / forward 测试）。§10 的候选 B（小仓位 forward 测试）因此成为唯一有信息量的方向。
