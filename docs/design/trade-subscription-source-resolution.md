# 成交订阅与行情来源确认

成交实时连接按来源、品种 ID 和 tickSize 定义身份，视口变化只调整历史成交需求，不应创建新连接。

原先首次协调可使用目录中的品种描述，而历史 K 线加载后又改用正式解析的描述。`loadBars` 在发布 K 线数据之后才保存正式来源，使首次数据通知与第一次拖动可能使用不同描述，造成一次多余的断连、重连和缓存重建。

成交与 K 线订阅现在统一由 `MarketRuntime` 监听 Kernel 的 `readyMarket` 快照管理。`loadBars` 先保存解析结果和来源能力，再迁移自动来源、合并 K 线数据；活动数据与就绪快照由同一个 Action 原子发布。显式来源和自动路由遵守相同顺序。运行模块的视口监听只调整历史成交需求，不再执行连接协调。

回归测试覆盖显式来源和自动路由，在目录 tickSize 与正式 tickSize 不一致时确认加载前没有连接、加载后只有一个连接、重复视口协调不会断开重建，销毁时释放连接。
