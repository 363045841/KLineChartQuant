# 未来槽位时间标签：无日历时的相对索引占位

## 背景

未来区几何只按逻辑 `index` 计算，日期文本来自数据源交易日历。当数据源没有日历能力，或日历未覆盖某个
未来槽位时，`getAxisTimestampAtLogicalIndex` 返回 `null`，此前的实现对未来区不显示任何时间标签。

这留下两个问题：

1. 未来区看起来像"没有时间"，用户无法判断当前留白对应多少个未来槽位。
2. 选中绘图落在未来锚点（`futureOffset`）时，`projectAxisDecorations` 直接格式化 `anchor.time`，
   而该字段是**创建时末根 K 线的时间**，于是显示了一个与槽位无关的日期。

## 决策

**未来区不再隐藏时间标签；没有权威时间戳时用相对索引占位 `T+X`。**

1. **占位语义**：末根真实 K 线记作 `T`，其后的第一个未来槽为 `T+1`，依次递增。`X` 是相对槽位偏移，
   不是日期，也不做任何日历推导。
2. **数据层保持诚实**：无日历仍返回 `null`（不知道就是不知道）。`T+X` 只发生在展示层，
   不写入 Buffer，也不回流到 `getTimestampAtLogicalIndex`。
3. **统一入口** `resolveAxisTimeLabel(index, dataLength, timestamp, formatDate)`：
   `timestamp` 非空即显示真实日期；为空且 `index` 是有效未来槽时返回 `T+X`；其余返回 `null`。
   X 轴刻度、十字线时间签、选中绘图锚点时间签共用该入口，口径唯一。
4. **未来刻度密度**：有日历时仍按日 / 月边界产出真实日期刻度；无日历时按 `1/2/5 × 10^n` 的整数步长
   抽样（相邻标签最小间距 56px，步长由槽位像素宽度推出），并**始终包含 `T+1`**，让未来区的起点可见。
5. **选中绘图的未来锚点**不再使用 `anchor.time`：锚点已随新 K 线变为真实 bar 时取该 bar 时间，
   仍在未来时只取交易日历，缺失则显示其当前索引的 `T+X`。

## 取舍

- **为什么不继续隐藏**：隐藏等于让"没有日历"和"这里是空白"无法区分；`T+X` 至少给出确定的槽位语义。
- **为什么不推导日期**：按工作日推测会越过法定假期，且会让不可靠的推导反过来决定几何——这正是本次工作
  要删除的旧算法。
- **为什么 `T+1` 固定显示**：整数步长抽样会让首个标签落在 `T+step`，未来区起点无标记；固定补一条 `T+1`。
- **为什么不用锚点自身时间兜底未来槽**：`anchor.time` 的既定语义是创建时基准 bar，不是槽位日期，
  用它当未来日期会静默显示错误信息。

## 影响

- 未来区在无日历数据源（如股票、港股）上也会出现时间标签，但文本为 `T+n` 而非日期。
- 日历存在但覆盖不到（如内置数据库截止 2027 年底）的槽位同样显示 `T+n`，与完全无日历口径一致。
- 分时 / 五日分时没有未来区（`futureScreens` 不作用于 timeshare），不受影响。
- 数据层、协议与后端接口均未改动。
