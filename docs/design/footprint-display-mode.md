# 足迹作为 K 线显示模式

## 归属与入口

FootPrint 是主序列内部成交分布的展示方式。`settings.klineShape = 'footprint'` 与实心、空心 K 线、美国线并列，数据视图保持 `kline`，周期不变。主序列模型从同一设置派生，不再持有独立的 K 线显示偏好。

足迹不注册为指标，不创建指标实例，不占用指标图例或结果池。旧指标定义、目录、Worker 特例以及指标层的成交输入、成交版本缓存和加载来源均移除，不保留自动添加隐藏指标或旧指标 API 的兼容通道。

当前品种缺少原始逐笔成交能力时，足迹图在“K 线形态”菜单中置灰，不进入该模式，也不请求成交。能力判断复用会话与品种能力位（`supportsRawTradeStream`），与成交流订阅共用同一份规则；无就绪会话时视为能力未知，不禁用入口。

## 数据与计算

链路为 `显示模式需求 → ChartDataManager / MarketRuntime → DataState.trades → FootprintState.input → 足迹执行器 → FootprintState.renderState → Layer / 自动价格范围`。

数据层拥有历史查询、实时连接、共享缓存、完整覆盖证明与取消请求。需求由足迹模式是否启用决定，切到其他 K 线形态或分时即释放成交使用权。切市场或周期时，活动行情快照与空成交在同一个 Action 中发布，旧成交不能与新 K 线混用。

足迹生效条件为“形态被选中且品种支持原始逐笔成交”。品种不支持时数据层发布空闲快照，不建立连接、不保留旧成交，图上既无足迹内容也无提示文案；成交不可用不伪装成零成交。

FootprintState 属于内核子状态。计算输入包含完整市场与周期选择身份、K 线、计算参数和成交快照；结果携带原输入身份，只允许当前输入提交。计算器继续按真实 K 线边界聚合，使用十进制定点运算与增量桶缓存。

专用 Worker 不加载指标目录。批次引用前缀一致时只传新增成交批次，历史替换或市场变化传完整快照。一个在途任务加一个最新待办，避免高频成交堆积；旧任务不提交，随后消费最新快照。退出模式或销毁图表时关闭 Worker、解除监听并释放私有聚合缓存。Worker 不可用时以相同执行核心在主线程运行，重新下发完整成交。

## 配置与绘制

足迹设置由 `DEFAULT_SETTINGS` 声明并随布局保存：分行方式、振幅周期、目标行数、每行跳数、不平衡倍数、成交量/成交额口径，以及 Volume / Delta / Bid Ask 文本模式。仅足迹模式显示这些设置，分行方式决定相关参数的可见性；隐藏时保留参数。文本模式只影响展示，不触发聚合。

足迹模式以空心 K 线绘制全部可见柱的实体轮廓与影线，不依赖历史成交是否就绪；成交分布在 K 线主体之后叠加绘制。哪些形态画成空心主体由 `chartSettings` 的 `HOLLOW_BODY_KLINE_SHAPES` 声明，蜡烛 Layer 只查这份清单，不再就地比较形态字面量，新增空心主体时也只改这一处。足迹复用主图时间与价格坐标、Scene 和覆盖画布；覆盖画布角色只表示实际绘制表面，不表示指标身份。自动价格范围合并完整价格档位宽度，手动轴范围仍优先。比较叠加继续沿用原有比较价格轴规则。

Bid 从柱中心向左延伸，Ask 向右延伸；可视区内两侧共用单侧数值上限。每行保留物理像素间隔，数字按整列可用高度统一决定是否显示，并校验文字宽度。Delta 汇总跟随柱脚，超出视口不吸附到底部。所有配色消费主题 Token。

`footprintMetric` 决定成交量或成交额展示，不平衡始终依据成交量；文字模式只选择合计、差值或 Bid/Ask 双列。不支持与错误信息直接来自足迹状态，不借用指标加载状态。成交缺失不伪装成零成交。

## 验证

复用领域行情与成交 Helper，测试覆盖增量追加、重复快照、历史替换、周期隔离、高频合并、过期提交、模式退出和销毁，以及文本切换不重算。绘制测试保留价格行裁切、DPR 像素对齐与文字布局断言，旧指标图例和注册用例删除。真实 Connector 用例直接执行足迹计算链路，仍由 `BINANCE_CONNECTOR_TEST_URL` 显式启用。

人工验收：`pnpm dev -c binance`，选择 Binance Spot / BTCUSDT / 1min，在“K 线形态”选择“足迹图”，进入图表设置调整足迹参数；滚动补历史，切品种、周期、分时和普通 K 线，检查成交内容、状态与订阅释放。
