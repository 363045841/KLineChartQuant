# 成交量分布的时间对齐

本文说明成交量分布（SVP / PVP）从数据源到落图的时间口径，以及已经修复与仍待处理的问题。
目标是让「交易日」「阶段边界」「明细窗口」三层各自可独立验证，避免按下葫芦起了瓢。

## 1. 三层模型

| 层 | 归属 | 负责什么 | 失效时的表现 |
| --- | --- | --- | --- |
| 数据源时间契约 | 各 connector | K 线时间戳的时区与含义（UTC 毫秒、开盘时刻） | 同一根 K 线在不同源上落在不同位置 |
| 会话配置 | `builtinMarketSessions.json` | 交易日边界、交易时段、交易日历 | 阶段起点偏移、周末缺阶段 |
| 指标对齐 | 脚本 + `volume-profile` 库 + 取数层 | 明细窗口、阶段分组、绘制锚点 | 阶段数量不足、分布缺失或错位 |

三层里任意一层出错，图上都表现为「分布不对」，所以必须分层验证。

## 2. 数据源时间契约

| 数据源 | 时间戳 | 时区声明 | 备注 |
| --- | --- | --- | --- |
| Binance（现货 / 永续） | UTC 毫秒，K 线开盘时刻 | 会话 `timeZone = UTC` | 官方按 UTC 日切分 |
| MT5 | 经纪商服务器时间换算成 UTC 毫秒 | 会话 `timeZone = UTC` | 服务器时区随经纪商，需按品种读取 |

两源的 K 线时间戳都是 UTC 毫秒，差异只体现在**交易日边界**，因此边界必须由会话配置表达，不能由脚本猜。

## 3. 会话配置

```jsonc
// Binance 永续：24×7，日界按 UTC 午夜
"BINANCE_PERP": { "timeZone": "UTC", "sessions": [{ "open": 0, "close": 1440 }],
                  "tradingDays": [0,1,2,3,4,5,6], "dayBoundary": { "time": "00:00", "zone": "UTC" } }

// MT5：不限星期，周末是否有 K 线交给经纪商与数据源
"MT5": { "timeZone": "UTC", "sessions": [{ "open": 0, "close": 1440 }],
         "dayBoundary": { "time": "00:00", "zone": "UTC" } }
```

要点：

1. `tradingDays` 只表达「配置层面确定的休市」，不代表行情存在与否。
   MT5 同时覆盖外汇、金属、指数与加密，钉死周一到周五会让加密品种丢掉周末。
2. `dayBoundary` 表达「换日时刻 + 时区」。加密按 UTC 午夜，MT5 按服务器午夜（对应北京 08:00）。
3. `time_tradingday` 优先读 `dayBoundary`，未配置时退回会话时区午夜。

## 4. 指标对齐

### 4.1 明细窗口

脚本通过 `request.security_lower_tf` 声明需要的 1 分钟明细根数。

- 选项在**声明期**求值，那里读到的参数可能还是默认值，所以窗口取
  `max(32 天, 保留期数 + 1)`，不依赖声明期的参数。
- 宿主按声明根数翻页取足，不再停在「覆盖图表首根」为止。

### 4.2 阶段分组

- 分组键：`time_tradingday`（交易日）。
- 明细**可能乱序到达**（增量执行、回滚历史、重复计算），所以按 key 归组后再按 key 升序，
  不能按「相邻段」切分。
- 保留期取最新的 N 段。

### 4.3 绘制预算

每个指标最多 2000 个绘图对象。每期占用 `行数 × 2 + 1`，因此：

- 保留期数超预算时**先压缩行数**（最少 24 行），折让后仍不够才削减期数；
- 活动期每轮重算前先删除上一轮图元，否则对象会跨 bar 累积，越过上限后静默淘汰最早的阶段。

## 6. 仍待处理

1. **亚像素宽度**：宽度按「阶段跨度 × 百分比」，日线上一阶段只有 1 根 K 线，缩小时不足 1 像素。
   修法：渲染层加最小 1 像素保底，或脚本按主图 K 线宽度计算。
2. **32 天窗口首载慢**：首次进入要取约 46000 根 1 分钟 K 线，分页 40 次上下。
   可取：窗口降到 16 天，或先画已到部分再补齐。
3. **PVP 阶段单位**：周 / 月阶段与日阶段混用时的对齐尚未单独验证。
4. **MT5 真实时段**：`SymbolInfoSessionTrade` 尚未接入，当前仍是全日画像。

## 7. 分层验证方法

| 层 | 验证 | 判据 |
| --- | --- | --- |
| 数据源 | 直接向 connector 请求 1 分钟 K 线，向前翻页 | 任意历史窗口连续、无断档 |
| 会话 | 单元测试 `timeValue('tradingday', ...)` | 指定时区的换日时刻返回预期交易日 |
| 明细窗口 | 页面内打印明细根数与首末时间 | 根数 = `max(32, 保留期数+1) × 1440`，首末覆盖预期 |
| 分组 | 测试环境用真实数据跑指标 | 阶段数 = 明细覆盖的交易日数 |
| 绘制 | 浏览器截图放大到最近几天 | 每个阶段都有柱体，宽度可见 |
