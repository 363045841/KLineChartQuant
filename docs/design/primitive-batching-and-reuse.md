# 原语合批、缓存与资源复用

本次不实现局部重绘、脏矩形或局部合成。各层仍在原有失效条件下整层重画，已有正式 drawing 与 session 的隔离保持不变。

圆、矩形、圆角矩形及带边框锚点使用同一套解析形状实例布局，位置、尺寸、半径、填充和描边颜色均为实例属性。相邻形状无论颜色是否相同均可合批，并保留实例顺序。线段与小型凸多边形使用连续顶点直绘；单条圆端线使用完整胶囊轮廓，透明端帽不会重复混合。复杂描边和多轮廓填充保留 stencil；只合并相邻、填充规则相同且包围盒不相交的 stencil 对象。

不透明描边不再走 stencil：轮廓展开后直接以三角形绘制。描边轮廓之间只在线段接缝与连接处重叠，不透明颜色下重叠不改变结果；而 stencil 需要为每条折线按包围盒铺一次 cover，全宽指标线等于每帧多出若干次全幅填充，这是多指标场景的主要 GPU 填充开销。半透明描边仍保留 stencil，避免接缝重复混合。

合批不改变原始命令顺序，不跨实例、网格、复杂路径或 Canvas 文字边界重排。文字继续由 Canvas 直接绘制，不生成字形纹理。混合图文批次使用复用的私有 staging 画布按顺序合成，成功后才写入可见目标，避免后半批 GPU 失败造成部分输出重复；纯几何不增加 staging。该方案明确接受图文交错时的提交边界，不能以把所有文字移到最后来换取合批数。

CPU 几何缓存以平移归一化的路径和样式、DPR 为依据，哈希后再精确比较源坐标快照，支持可变数组并避免碰撞误复用。颜色不参与 tessellation 失效，平移只改顶点位置。缓存限制为 1024 条且总量不超过 64 MiB；淘汰按批进行，同一批内使用到的条目不参与淘汰，避免同帧先建的几何被后建的几何挤出，导致下一帧整批重建。坐标和几何使用双精度保存，最终写 GPU buffer 才转为 Float32。原始包围盒（描边按 miter 上限扩展）在 tessellation 前剔除完全在屏幕外的对象。

CPU 顶点和实例缓冲按容量增长，GPU buffer 复用同样的连续布局。每种数据每段最多一次上传，CPU 镜像比较后只上传实际变化的连续区间；未变化的数据零上传，但仍整层绘制。WebGL 移除逐对象 bufferData、白色纹理上传和热路径 getError。WebGPU 复用 viewport uniform 与绑定，减少重复管线设置。常见 hex 颜色直接解析，其他 CSS 颜色通过后端私有有界缓存复用浏览器解析结果。

`PrimitiveBackend.getMetrics()` 暴露最近一批的输入数、剔除数、几何命中/构建数、实际 draw、上传次数/字节、submit、合成次数和 CPU 准备/提交时间。`waitForIdle()` 仅供基准使用。完成等待时间不等于 GPU timestamp；未经 timestamp query 测量不声称 GPU 执行耗时。真实浏览器回归与性能计数入口沿用 `bench/primitives.html`。

本机 Chrome 已通过三后端、DPR 1 / 1.25 / 1.5 / 2 的像素回归，另检查透明实例顺序、独立 stencil 区域重叠、锚点边框、可变路径失效，以及图文混合后半段故障的原子回退。性能计数场景包含 4096 个圆/圆角矩形、128 条线和 256 个屏幕外圆：WebGL2 与 WebGPU 都剔除 256 个对象，以 2 次 draw、1 次 submit 完成整层绘制；重复绘制时 128 条线命中几何缓存，几何构建数和上传字节均为 0。此计数只证明该场景的合批和资源复用，不声称任意图文交错或透明复杂路径都能压缩为两次 draw。

## 帧内合成与矩形批次

逐层合成会让每个 Layer 各付一次全目标离屏渲染与整张拷贝，成本与层数成正比而不是与内容成正比。现在由 Scene 为每个绘制目标建立一个合成器（`primitives/impl/composer.ts`）：连续输出原语的图层累积成一批，帧末统一落盘，每个目标每帧只做一次离屏渲染与合成。只有在目标级状态（仿射变换、透明度、合成模式、阴影、滤镜）变化时才切段，切段时按提交时记录的状态重放，不改变坐标与透明度语义。

参与跨层合并的图层必须在类型上声明为 `kind: 'draw-list'`：它们的绘制上下文不含 `ctx`，只能提交原语，因此写不出裁剪、清屏、读回或坐标系修改。其余图层是 `kind: 'context'`（缺省），Scene 在其前后立即合成，保证层级顺序与自带的裁剪语义不变。蜡烛层与 Plot 层是 `draw-list`，所以主图上"蜡烛 + 全部指标"共享一次合成。

柱体不再逐根生成图元：同色柱体是一个 `rects` 批次原语（`Float64Array`，每 4 个数一个矩形），后端一次实例化绘制，业务层不为每根柱子分配对象。投影端的屏幕缓冲按世界缓冲复用，也不每帧分配。GPU 目标的 drawing buffer、WebGPU 的深度/模板纹理按目标尺寸只增不减，多 pane 交替绘制不会每帧重建销毁；离屏设备不再开启 `preserveDrawingBuffer`，合成后不保留上一帧内容。若一批内容在逻辑像素上的覆盖面积低于目标的 6%，直接交给 Canvas 绘制，避免为几乎空的批次付整张离屏与合成成本。

## 解析式描边

指标线的成本不在填充率，而在每帧的三角化与顶点搬运：`strokePaths` 对每段生成四边形、对每个可见折点生成一个圆，1px 折线约每点 36 个顶点，线数增加时 CPU 写入与缓冲上传按线数线性增长；Canvas 后端交给浏览器原生 stroke，没有这两笔开销，因此同一批指标在 GPU 后端反而更慢。

WebGL2 与 WebGPU 后端都提供 `segments` 绘制：不透明、实线、圆角连接与端帽的开放折线不再三角化，顶点缓冲只保留每段端点与相邻端点（每段 14 个 float：起点、终点、前一点、后一点、半宽、颜色、数据空间标记），每段一个实例，6 个顶点在 vertex shader 里扩成相邻三段 capsule 的轴对齐包围盒，片元着色器按到线段的最小距离计算覆盖率（`aa = 1/dpr`），输出预乘 alpha。圆角连接就是相邻胶囊的并集：覆盖率取本段与前后两段的最小距离，像素归属按端点角平分面切给一侧，共享圆盘因此只混合一次，不会在线身软边之外叠出一圈硬边小结。

归属规则只在同一条折线内部成立：相邻两段用同一个角平分面（`normalize(u_prev + u_this)`，180° 折返退化为与两段都垂直的方向）把共享圆盘对半分，末端取背面（含平面本身）、起始端严格取正面；折线首尾没有相邻段时法线为零向量，表示不裁剪。折线自身在两像素内折返时，两个不相邻的实例可能同时拥有同一个像素，那里仍会多混合一次。细节与取舍见 `docs/design/rendering/segment-join-union.md`。

只有半透明、虚线、miter/butt 端帽与闭合路径继续走原有三角化与 stencil 路径。半透明折线在旧实现里因接缝重复混合必须留在 stencil 并集；归属+并集已经不再依赖不透明度，但把半透明折线也切到解析式描边会同时改变其边缘质量与自交叠色，属于独立决策，本次不动。`createPrimitivePreparer` 的 `segments` 选项决定准备器是否产出该绘制；两个 GPU 后端都开启该选项，因此共用同一份准备器代码。

## 数据空间与帧变换

指标几何与滚动、价格轴无关时不必每帧投影到屏幕坐标。`DataTransform`（`offsetX` / `yScale` / `yOffset`）由本帧价格轴的线性映射推出，只有线性轴可用；数据空间的点保留世界 x 与价格 y，屏幕坐标在着色器里按该变换还原（x 减 `offsetX`，y 乘 `yScale` 再加 `yOffset`）。

因此滚动与缩放只改 uniform，不重写顶点缓冲，也不重新三角化。缓存 key 按半屏分桶（可见 K 线数的一半，至少 2 根）：纯滚动时桶不变，几何缓存命中；越过桶边界才重新投影。

世界坐标与滚动量分别对齐到物理像素（`round(worldX * dpr) - round(scrollLeft * dpr)`）。若对 `world - scroll` 整体取整，每个点的舍入方向会随滚动变化，几何缓存会每帧失效。

数据空间现在同时覆盖折线与填充带。`buildFillBands` 把同色相邻四边形合并成上下两条等长链，准备器用 `bandTriangles` 按段展开成零重叠条带，整条带子一次直绘，不再逐四边形走 stencil。带子顶点保留世界 x 与价格 y，网格着色器按 `DataTransform` 还原屏幕坐标（顶点上的 `mode` 标记区分屏幕几何与数据空间几何），因此滚动只改 uniform。

带子的路径数组引用与样式不变时，准备器直接跳到上一帧写好的顶点段并复用同一个 draw；`changed.vertices` 为 false，GPU 后端跳过整块上传比较。路径只有在数据或窗口分桶变化时才会重新分配，所以纯滚动不再重写或上传填充顶点。

`DataTransform` 随提交链路传到每个后端，没有例外：GPU 后端写进 uniform，Canvas 后端在 `appendPaths` 里用同一组参数写路径。后端包装层丢弃该参数会让数据空间折线回到价格坐标（y 约为数千）而整段不可见，因此新增后端或包装时必须把变换一路透传。

### 批级复用

`segments` 的实例布局在滚动与轴缩放时完全不变，因此准备器按原语位置缓存上一次的段范围：当前原语的路径数组引用、颜色、线宽、连接与端帽都与上一帧一致、且游标落在同一偏移时，只推进 arena 游标而不重写实例。`PreparedBatch.changed` 标出三类缓冲是否真正写入，GPU 后端据此跳过整块上传比较。

复用依赖“几何数组在两次绘制之间不可变”：投影层只有在数据或窗口分桶变化时才重新分配点数组，因此引用相同即可视为内容相同。若未来有生产者原地修改点坐标，必须改为重新分配数组或提供显式版本。

## 柱体可见区间与屏幕缓冲复用

蜡烛 Layer 的世界缓冲跨帧保留（`ensureBufferCapacity` 只增不减），投影端据此按世界缓冲缓存屏幕缓冲和原语对象：每帧不再分配 `Float64Array`，只把与视口横向相交的柱按下标紧凑写入，长度收窄为本帧可见柱数。视口外的柱在投影时就被跳过，合批阶段的 `rects` 长度即可见柱数，10,000 根的批次不再让 `prepare` 逐根扫描，也不再为整段历史付量化成本。

这里没有对 `rects` 引入二分查找：空心蜡烛的边框与实体共用一个批次，宽度不同，`x + width` 不保证单调，维护这条契约的风险大于收益；线性判定每根只需两次数组读取，不需要除法与写入。纵向裁剪仍留给消费端，柱体只需要时间轴方向的裁剪。

## Canvas 矩形剔除与数据空间路径缓存

Canvas 后端（`canvas.ts`）在提交矩形批次前逐根剔除视口外的柱：此前整批 `fillRect` 都会落到主线程，视口外部分只靠浏览器裁剪。单形状与路径不做逐原语包围盒剔除——它们的提交量已由可见窗口投影限制，额外扫描省不到成本，还会改变贴边几何的绘制结果。

数据空间填充（Ichimoku 云带）按路径数组引用缓存 `Path2D`：纯滚动与价格轴缩放只改变换矩阵（`translate` + `scale`），不再每帧逐点 `moveTo`/`lineTo`。缓存前提与 GPU 准备器相同——投影层按窗口分桶重新分配路径数组；没有 `Path2D` 的环境（jsdom）退回逐点写路径。数据空间描边不缓存：纵向 `scale` 会把 1px 线宽压成非各向同性的截面，指标线必须保持等宽。

GPU 上的半透明云带成本是填充率而不是几何：带子已按零重叠条带三角化，顶点也按引用复用，剩余开销只与屏幕上的覆盖面积有关。目标级 MSAA 已关闭，解析 AA 由 segment/shape 着色器承担，三角化边缘（云带、非解析描边、stencil mask）不再有多采样平滑；这类边缘的可见性取决于是否被同色或相邻的解析线条覆盖，无边界线的填充需要显式描边。
