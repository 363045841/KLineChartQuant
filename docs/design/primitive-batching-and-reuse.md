# 原语合批、缓存与资源复用

本次不实现局部重绘、脏矩形或局部合成。各层仍在原有失效条件下整层重画，已有正式 drawing 与 session 的隔离保持不变。

圆、矩形、圆角矩形及带边框锚点使用同一套解析形状实例布局，位置、尺寸、半径、填充和描边颜色均为实例属性。相邻形状无论颜色是否相同均可合批，并保留实例顺序。线段与小型凸多边形使用连续顶点直绘；单条圆端线使用完整胶囊轮廓，透明端帽不会重复混合。复杂描边和多轮廓填充保留 stencil；只合并相邻、填充规则相同且包围盒不相交的 stencil 对象。

合批不改变原始命令顺序，不跨实例、网格、复杂路径或 Canvas 文字边界重排。文字继续由 Canvas 直接绘制，不生成字形纹理。混合图文批次使用复用的私有 staging 画布按顺序合成，成功后才写入可见目标，避免后半批 GPU 失败造成部分输出重复；纯几何不增加 staging。该方案明确接受图文交错时的提交边界，不能以把所有文字移到最后来换取合批数。

CPU 几何缓存以平移归一化的路径和样式、DPR 为依据，哈希后再精确比较源坐标快照，支持可变数组并避免碰撞误复用。颜色不参与 tessellation 失效，平移只改顶点位置。缓存限制为 256 条且总量不超过 8 MiB；坐标和几何使用双精度保存，最终写 GPU buffer 才转为 Float32。原始包围盒（描边按 miter 上限扩展）在 tessellation 前剔除完全在屏幕外的对象。

CPU 顶点和实例缓冲按容量增长，GPU buffer 复用同样的连续布局。每种数据每段最多一次上传，CPU 镜像比较后只上传实际变化的连续区间；未变化的数据零上传，但仍整层绘制。WebGL 移除逐对象 bufferData、白色纹理上传和热路径 getError。WebGPU 复用 viewport uniform、绑定及 MSAA 目标，减少重复管线设置。常见 hex 颜色直接解析，其他 CSS 颜色通过后端私有有界缓存复用浏览器解析结果。

`PrimitiveBackend.getMetrics()` 暴露最近一批的输入数、剔除数、几何命中/构建数、实际 draw、上传次数/字节、submit、合成次数和 CPU 准备/提交时间。`waitForIdle()` 仅供基准使用。完成等待时间不等于 GPU timestamp；未经 timestamp query 测量不声称 GPU 执行耗时。真实浏览器回归与性能计数入口沿用 `bench/primitives.html`。

本机 Chrome 已通过三后端、DPR 1 / 1.25 / 1.5 / 2 的像素回归，另检查透明实例顺序、独立 stencil 区域重叠、锚点边框、可变路径失效，以及图文混合后半段故障的原子回退。性能计数场景包含 4096 个圆/圆角矩形、128 条线和 256 个屏幕外圆：WebGL2 与 WebGPU 都剔除 256 个对象，以 2 次 draw、1 次 submit 完成整层绘制；重复绘制时 128 条线命中几何缓存，几何构建数和上传字节均为 0。此计数只证明该场景的合批和资源复用，不声称任意图文交错或透明复杂路径都能压缩为两次 draw。
