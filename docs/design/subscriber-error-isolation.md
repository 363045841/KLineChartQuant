# 状态通知的订阅者隔离

StateKernel 的状态通知是全部消费者的公共总线：同一个信号可能同时驱动数据层、指标执行、渲染调度和框架桥接。通知是同步派发的，任何订阅者抛出异常都会中断本轮剩余订阅者，造成"状态已经写入、但界面和渲染没收到"的整页停摆。实时流能力协商曾经就是这样：connector 声明了 `liveBars` 而前端没有工厂，运行时在 session 通知里抛错，数据已进 Buffer，loading 与重绘通知却被截断。

因此 `createSignal.set` 与 `batch` 的落盘循环逐订阅者隔离：单个订阅者失败只上报到控制台，其余订阅者照常收到本次状态。隔离只作用在通知边界上，订阅者自身的半成品状态仍由订阅者负责；构造期错误、同步调用期的错误仍然正常抛出，不在这里吞掉。

业务错误应当在自己的边界内处理：能力协商在 probe 入库时归一化，建流失败只跳过该序列；通知链不再承担跨模块契约校验。这样底座只保证"一次状态写入对所有消费者可见"，不再让一个模块的错误决定其他模块能否收到状态。
