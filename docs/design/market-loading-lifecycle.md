# 行情加载与工作台恢复

## 单一历史加载入口

`ChartDataManager.loadBars` 负责首批查询、向前分页和失效重查。三种操作共享请求身份、取消信号、loading、来源元数据、Buffer 提交及加载完成通知。失效重查使用缓存的 `refreshBars` 清除旧页，再在同一加载流程中替换完整快照；分页继续合并已有快照。

`MarketRuntime` 只持有实时订阅及其生命周期，向数据管理器提交重查需求。重查期间的单根事件按接收顺序排队，在快照完成后重放；注销或切换会话后，旧回调失效。运行模块不再另写一套历史请求与提交流程。

失效重查完成必须通知正常视口缺口检查，即使第一根时间戳没有变化。交易日历的请求记录与旧日历在新快照通知前失效，避免绘制订阅读取旧日历，或把通知期间恢复的日历再次清空。

每个加载任务只能释放自己拥有的 loading。取消立即释放该状态，不等待不遵守 AbortSignal 的数据源结束 Promise；过期任务不能提交快照，也不能清理后续任务的 loading。

## 品种错误归品种选择管理

`useWorkbenchMarket` 管理当前品种的解析、错误和取消。解析错误作为局部状态呈现，并通过工作台 error 事件通知宿主，不再向异步组件 setup 或 watcher 抛出。品种查询不阻塞工作台初始化，网络等待期间仍能挂载图表和 Agent。重试、更换品种、重新注册来源都使用同一解析操作，保留图表、Agent 和脚本服务实例。来源身份变化时重新解析，过期结果不会覆盖新选择。

工作台外层错误边界仍处理组件或服务初始化异常；行情业务错误不再进入该边界。

## 删除旧注入通道

删除 Chart、ChartDataManager 和 ComparisonManager 的数组注入方法及专用辅助逻辑，不保留兼容入口。依赖旧方法的测试及 bench 注入调用直接删除，不迁移为另一套测试注入入口。底层 Buffer/store 仍承担正式缓存和实时管线的数据提交。

回归验证从注册数据源进入真实缓存、数据管理器和实时运行模块，覆盖刷新后的缺口回填、日历恢复、增量顺序和取消状态；工作台测试覆盖解析失败后的重试、切换和来源恢复。
