# 编译产物与编译线程分开管理生命周期

真实 Binance 页面加载 PVP 和 MACD 后，Compiler Worker 在两次间隔 12 秒、均执行 GC 的采样中仍保留约 25.8MiB 已用堆和 9.8MiB backing storage。已安装的计算模块不依赖 TypeScript VM，但原先编译线程与活动源码租约绑定，指标存在期间编译线程就不能退出。

现在源码租约只管理源码、依赖与已编译产物缓存。只有缓存未命中的新编译请求才创建物理线程；全部请求完成后保留一秒空闲窗口，以复用启动注册和连续保存中的相邻请求。窗口内没有新编译则终止线程，回收整个 TypeScript VM。命中已有产物不创建线程，新源码在需要时重新启动线程。

在途请求禁止回收。新请求取消空闲计时器；最终租约释放、线程故障和消息读取故障都会取消计时器并释放物理线程。事件处理验证线程身份，已经回收的线程即使延迟发送事件，也不能影响后来创建的线程。线程故障拒绝在途请求，后续调用创建新宿主；已安装的执行模块保持独立。

一秒窗口只用于合并编译突发，不是指标计算超时，不参与行情或任务版本判断。代价是长时间不编译后的首次新源码需要重新加载编译器；已编译指标的参数修改与行情计算不需要重新加载它。

验证分为真实页面的关闭线程诊断、修改后的 Worker 创建与回收观测，以及租约缓存、并发请求、故障、退出事件和销毁的单测。不同 Worker 的堆数值与进程私有内存分开报告，不直接相加作为物理内存降幅。

同页诊断中，关闭编译线程前后保持 601 根行情和 238 个 PVP 绘图对象，Renderer 私有内存从 330.2MiB 降到 281.9MiB；其他轮次下降幅度有波动。修改后真实页面稳定状态只剩两条计算 Worker，两个新源码版本都能重建编译线程并在完成后自动释放；租约仍持有的缓存产物在释放线程后保持可用。新版本首次编译耗时约 453ms、404ms。PVP 参数重算通过；本轮未观察到持续实时推送，因此不声称已经验收持续实时更新。
