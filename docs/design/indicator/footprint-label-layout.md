# Footprint 价位数字的整列布局

## 决策

Footprint 每根柱的价位数字（Bid / Ask）以**列**为单位决定显示与否：同一根柱要么每个可见价位都画数字，要么整列都不画。字号在列级别算一次，不再逐行独立判定。

## 原因

原实现按行判定，条件是"本行文字底部 + 2px ≤ 上一行文字顶部"，其中行高来自 `roundToPhysicalPixel` 逐边取整、字号来自该取整行高。真实行距通常不是物理像素的整数倍，逐边取整会让计算出的行高在 `floor(行距*dpr)/dpr` 与 `ceil(行距*dpr)/dpr` 之间逐行交替；字号（被 `max(8, ...)` 钳死）与文字基线随之交替，最终与硬编码 `2px` 阈值比较时判定逐行翻转。

结果是同一列在视觉完全相同的行距下出现"有的行有数字、有的行没有"，且多数发生在行距刚好落在阈值附近时（例如 DPR=1.5、行距约 11.2px 时 60 行会孤立地丢掉 1 行）。这是像素取整误差被放大成离散判定的问题，与数据无关。

## 实现

- 新增 `resolveLabelFontSize(cells, priceToY, rowSize, width, dpr)`：取该列**未取整**的相邻价位屏幕间距最小值 `minPitch`，按最坏情况（取整后可能少一个物理像素）`snappedPitch = floor(minPitch * dpr) / dpr`，从 `snappedPitch - LABEL_GAP` 推出字号；放不下 `MIN_LABEL_FONT_SIZE` 时返回 `0`，整列不画。
- 逐行绘制只保留两类真实裁切：文字超出 pane 上下边界，以及单侧文字宽度超过半柱宽。删除 `previousLabelTop` 重叠判定——既然整列行距一致且字号由最坏行距推出，相邻标签必然不重叠；真正稀疏（缺档）的价位间距只会更大。
- 物理像素对齐保持不变：柱体矩形仍用 `roundToPhysicalPixel` 取整，文字落点 `textY` 仍取整；改动只切断"取整行高 → 字号/阈值"这条链。
- 硬编码 `40` 提取为 `MIN_LABEL_COLUMN_WIDTH`，与字号、间隙常量集中声明。

## 取舍

- 列内行距不一（对数价格轴）时以最小行距定字号，意味着最宽的行也用同一字号，可能比逐行自适应更小；换来的是"整列一致"这一确定行为。
- 行距刚好放不下最小字号（如 9.7px）时整列不画，而旧实现会画一半。这是"全有或全无"的必然结果，避免视觉上看起来像随机丢字。
- 测试以 `rowSize=10.5`（整列 12 行全画）与 `rowSize=9.7`（整列 0 行）固定该不变量；旧实现在这两个行距下分别为 6/12 与 8/12。
