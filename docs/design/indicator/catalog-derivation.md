# 指标展示目录的派生

## 背景

指标定义的唯一事实来源是**定义注册表**（`indicatorDefinitionRegistry`）。选择器与参数面板
读取的「展示目录」（`indicatorCatalog`，把注册表条目映射为 `Indicator` 展示项）曾把它复制进
一个模块级数组，并用「定义数量是否变化」决定是否重建。

数量判断天生漏掉「更新」：脚本改动已有定义的 `input` 时，定义数量不变，缓存永不失效，
参数面板与选择器因此一直显示旧参数；同名更新、改默认值、改标题都会中招。

## 决策

**展示目录是注册表的只读派生，不再保存影子缓存。**

- 注册表维护一枚 `catalogRevision`，`create` / `update` / `remove` 及测试清空都会推进它。
- `getIndicatorDescriptors()` 读取该修订号，使任何读取它的派生视图自动建立依赖。
- 展示目录改为响应式 `computed`：修订号变化时由响应式系统重建，没有手工失效判断。
- `computed` 在**首次读取时**才创建，保持内置目录的懒登记（避免在模块导入阶段抢先登记，
  破坏按需加载的时序）。

## 提交顺序不变量

修订号必须在**通知消费者之前**推进：

```
写入目录 → 推进 catalogRevision → 通知订阅者
```

订阅者收到通知时读到的新修订号必须已经对应提交后的状态。旧实现「先通知、后推进」，
订阅者重建目录时拿到的是旧修订号，更新因此不生效。

## 结果

- 展示目录、选择器、参数面板共享同一派生源；更新脚本参数即时反映。
- `getIndicatorCatalogRevision` 这类为手工比对而存在的读取口被删除；依赖由派生本身表达。
