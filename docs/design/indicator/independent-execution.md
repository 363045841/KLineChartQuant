# 指标执行与资源生命周期

## 问题与决策

实时输入更新、结果过期和资源取消是三个不同事件。旧实现把每个行情版本都作为取消边界，连带取消历史分页，并终止正在运行的Worker。其结果是历史重复请求、编译模块反复加载，以及加载圈无法准确表达任务状态。

执行链路现分为四个职责明确的模块：

1. `IndicatorBarsRepository`维护行情需求、共享历史准备和快照读取。`MarketRuntime`协调公共实时订阅，仓库通过bind端口登记需求，不管理线程或指标结果。
2. `createInstanceCalculationScheduler`拥有计算身份的运行任务与最新待执行输入。执行端口一次只接收一个任务、一个输入和一个生命周期信号，不再使用全局setData加整批execute。
3. `createScriptWorkerPool`维护固定上限的线程、FIFO队列和每线程编译缓存。它不了解行情版本、指标轻重或实例关系。`prepareScriptMarketData`在池外异步准备快照，网络等待不持有线程。
4. `InstanceResultStore`是已发布结果的唯一仓库。它按当前计划映射实例，保留每份结果自己的时间轴；渲染和加载圈不反向控制取数或线程。

## 实时输入

每个计算身份最多存在一项运行任务和一项最新待执行输入。相同数据/行情依赖版本复用现有任务或已完成结果；新版本只替换待执行输入。连续30次更新不会产生30次并发计算，也不会终止原任务。

运行完成后立即提交该身份的结果，再执行最新输入。仍有新输入时保持加载状态。允许展示同一执行域中较早完成的快照，防止高速实时行情下始终无法发布；结果按完成顺序及数据版本单调前进，不允许旧任务覆盖新会话、已删除身份或较新的结果。每份结果包含自己的时间轴，不把旧数组套用到新K线下标。

计算函数与结果规范化只负责一项任务的数值及错误，不拥有数据版本缓存、取消控制器或整批等待屏障。调用者等待compute返回只用于操作结束通知，不决定其它指标是否可以上屏。

## 取消边界

普通tick和目标周期实时帧更新不取消运行任务。删除最后一个实例、修改计算参数、替换源码、切换行情执行域以及图表销毁才撤销对应身份的生命周期。源码更新只影响对应定义；其它指标继续运行。

取消排队的Worker任务直接移除。显式取消正在同步执行的脚本时，终止它独占的线程，后续按需重建。普通脚本错误不销毁线程；线程故障会重建。取消后的异步prepare不能把编译快照写入新线程的槽位。

## 行情需求

行情需求身份由来源、品种、周期、复权、聚合方式、请求模式和预算组成，独立于每次实时计算的版本。当前品种在分页前建立实时订阅；历史加载期间收到的新事实优先于较早的历史快照。多个计算使用者共享同一需求，最后一个退出、会话切换或图表销毁时才中止分页。

历史范围未扩大且实时尾部已经覆盖时，重算只读取公共Buffer。需求范围扩大时补历史；当前准备尚未完成时先复用它，不取消重启。脚本等待被取消只撤销等待者，不拥有历史任务的取消权。

## 状态与验收

加载状态直接由计算身份是否有运行/待执行任务派生；已有旧结果也显示。单个任务完成只结束自己的等待，不遍历结果池关闭其它指标的加载圈。最后一个待执行输入完成或明确失败/取消后结束等待。

测试以行为验收替代旧生态的实现镜像：连续更新合并、独立快慢任务、相同身份共享、参数/源码替换、执行域重置、错误恢复、历史准备共享、SSE事实不被历史覆盖、线程与编译缓存连续复用、显式取消隔离。删除旧setData/整批execute测试接口及其可控替身，不保留兼容执行链路。

线程池有并发上限，满载任务按FIFO等待；不引入轻重分类、动态优先级或用户调度参数。
