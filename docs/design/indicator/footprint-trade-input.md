# Footprint 与成交输入

Footprint 沿用现有 Provider → ChartDataManager → 指标计算计划 → 实例结果投影 → Layer → Scene。
定义通过 `@Indicator` 声明 `runtime.inputs: ['trades']`，不拥有网络、独立画布或 PluginHost 安装周期。

成交属于 Provider 能力，与报价 tick、盘口增量严格区分。历史使用左闭右开时间范围，实时按原始
tradeId 排序和去重；品种、来源变化取消旧请求。加载、缺口、不支持和错误通过只读快照传入指标。
完整覆盖的空柱可显示零量，缺失成交的柱不伪装为零量。

价格和数量保持十进制字符串，聚合使用 BigInt 定点运算；绘制边界才转为浮点坐标与紧凑文字。
柱子按实际 K 线开盘时间二分定位，历史插入不依赖旧数组下标。每个执行器创建自己的 calculator，
批次身份不依赖对象引用，Worker 结构化复制不会导致历史重复累计。

旧 FootprintController、tick-rule/Lee-Ready 分类器及 ingestTrade 兼容别名全部删除。
主动方向只接受真实交易所标记；不接盘口来推断成交。

Binance Connector 新增 `/trades/range`：已结束日期读取 SHA256 校验归档，当日通过 aggTrades
的 firstTradeId 定位原始历史成交，再校验连续 ID 分页。聚合成交仅定位游标，不参与足迹数量统计。
目录声明 BINANCE_SPOT UTC 会话，与前端通用 Provider 契约一致。

首期资源预算为单次七天、250000 笔成交及 250 页；超限显式报错，用户需缩小范围。
数字仅在柱宽与价格行高足够时显示，缩小时保留价位色块；虚线标记部分覆盖。

足迹横条以柱中心为起点，Bid 向左、Ask 向右，长度按数量线性缩放。可视区内所有柱、价位及
两侧共用最大单侧成交量作为比例上限，零量不绘制横条。行间留物理像素间隔，不平衡侧加深并
加粗数字；缩放或滚动改变可视区时重新确定数量比例。价格档位高度仍由主图价格轴决定。
Topbar 的复权方式右侧提供 K 线形态 DropMenu，可选择实心或空心 K 线；空心形态保留边框
和实体外影线，不用背景填充内部，配置随图表设置持久化。

执行运行时按数据版本、成交版本和计算身份缓存结果；纯 K 线指标不随成交更新重算。
每个计算身份独立拥有增量 calculator。Worker setData 仍走同一协议，只在批次前缀一致时发送追加批次，
替换、重同步与缓存压缩则发送完整快照。删除实例时回收其 calculator 和结果缓存。
视口手势停下 200ms 后更新成交需求，查询右界为最后可见柱的边界，历史查看不请求到当前时刻。
Buffer 按完整覆盖区间扣除缓存，单一任务按 UTC 分钟顺序补缺页；在途页不因手势取消并重拉。
实时订阅水位之后只消费 SSE，不能随时钟变化轮询 REST。成功页保留用于往返滚动，失败页以稳定
分钟身份记录，重连和缩放不自动重试。只有达到缓存预算才回收可视范围外数据；可视范围本身超限
时停止加载并提示缩小范围，禁止在每次滚动时删掉缓存。

人工验收：`pnpm dev -c binance`，选择 Binance Spot → BTCUSDT → 1min → 添加 Footprint。
调整“每行价格跳数”和柱宽查看 Bid × Ask；向左滚动验证补历史；切换品种/周期与删除指标验证取消订阅。
真实集成测试通过 BINANCE_CONNECTOR_TEST_URL 显式开启，核对完整分钟的原始逐笔总量与 Binance K 线量。
