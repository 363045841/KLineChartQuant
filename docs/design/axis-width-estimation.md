# 统一轴宽估算

主图、副图和自定义脚本共用最终轴标签收集结果，按字符组成、字号、加粗和留白估算所需逻辑像素宽度，不使用 Canvas 文本测量。左右轴分别取所有可见 Pane 的最大值，并保留配置的最小宽度。

估算器保留未重绘表面的结果，刷新十字线时不会丢失静态刻度宽度；删除或隐藏 Pane 后移除其记录。精度、正负号、单位、百分比、字号及倒计时通过实际文本自然影响估算。

标签由现有 Scene 绘制阶段生成，因此本帧收集完成后提交宽度；宽度变化时调整轴画布，使用保留的标签同帧重画轴，不重跑主图和指标。估算采用保守字符宽度，允许不同系统字体下存在少量留白差异。

## 列几何是唯一来源

逐轴估算结果不直接用于排版：`Chart.commitAxisWidths` 先把配置下限（`rightAxisWidth + priceLabelWidth`）
夹进总宽，再由 `layoutAxisColumns` 把它展开成 Pane 内的列几何，差额并入主轴列，
保证 `Σ列宽 === 该 Pane 的 axisWidth`。提交结果写入 `Pane`，同一份数据同时驱动：

- 轴列标签与区间带的绘制位置；
- 轴 canvas 的尺寸（不再测量父元素 `clientWidth`，避免滞后一帧）；
- 轴命中测试；
- 宿主控件区宽度（`paneGeometry.axisWidth`）与右栏总宽（`rightAxisEffectiveWidth`，首帧前取配置下限占位）。

只有最宽的 Pane 吸收下限差额，其余 Pane 的列宽按自身标签需求展开；右栏宿主宽度取
各 Pane 轴区宽度的最大值。禁止在消费方再次夹下限或自行测量，否则同一右栏会出现多个宽度。
