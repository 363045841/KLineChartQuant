# Plot 数据几何与帧重放

## 问题与边界

2026-11-11 的浏览器 trace 中，时间轴优化后，Plot 几何重建仍约占
2.08ms/帧，GPU 原语准备与上传链路约占 1.63ms/帧。
这些是 CPU 成本；WebGPU 不能自动消除逐点投影与缓冲比较。

原有 Plot 把价格提前转换成屏幕 Y，自动价格范围变化就会让全部路径失效。
上传端随后逐 float 比较一份 CPU 镜像，进一步重复遍历刚生成的几何。

## 坐标空间是几何契约

- K 线视图、线性轴上的折线和阶梯线保留世界 X 与价格 Y。
  滚动和价格缩放只更新帧变换，不重建路径。
- 对数轴、非 K 线横轴以及柱体、散点、标记按屏幕几何契约投影。
  固定像素宽度、字形避让与相对位置不能直接用价格仿射变换代替。
- 填充两端始终采用相同坐标空间。若填充连接了数据折线与屏幕图形，
  整个填充连通分量使用屏幕坐标，禁止在一个多边形中混用价格和像素。

每个 Plot 按自己的输入保留投影；一个像素图形改变不会让旁边的数据折线失效。
填充按两端投影和填充声明的身份复用。缓存按实例持有，卸载和已删除图形都会清理。

## 有界窗口与版本

数据折线的窗口大小取不小于视口像素容量（宽度 / 槽距）的最小二次幂，窗口两端各留一桶。
不使用可见整数槽数决定桶大小，避免滚动时槽数相差 1 就跨越二次幂边界。
窗口内滚动复用点数组；跨桶、缩放、Plot 数据/样式更新和坐标空间切换会重建。
版本只包含真正改变数据几何的输入，不包含滚动量、价格范围或逐帧中心点数组。

序列遍历只取投影窗口与序列的交集，正 offset 的未来点使用同一规则，
不再额外枚举所有屏幕外的未来数据。

Plot 和路径点是不可变快照：数据与样式更新产生新 Plot。
准备器快照原语描述符与路径列表，因此调用者可以复用原语列表容器。

## 描边在屏幕空间扩宽

WebGL 与 WebGPU 共用数据空间圆连接描边：缓冲存端点及相邻点，
顶点着色器先应用帧变换，再按固定逻辑像素扩宽与计算角平分面。
现有共享 shader 已具备这项变换；准备器现在允许数据空间圆连接进入该路径。

虚线、半透明、闭合路径及非圆连接先转换端点，再进入既有屏幕描边算法。
这是按样式选择几何算法，不是另一套 Plot 实现；线宽、dash 与 miter 不会使用价格单位。
Canvas 同样只转换端点，然后以原始像素线宽 stroke，不缩放 Canvas 的描边矩阵。

GPU 缓冲使用批次局部原点：世界坐标与价格先在双精度中减去原点，再写 Float32。
后端在双精度中合并原点与帧变换，避免长历史、大价格和小价差在 GPU 上出现精度抖动。
原点改变时，数据缓冲全部重新编码。

## 写入者声明上传区间

`FloatArena.reserve` 声明将写入的区间，`write` 写数据，`skip` 复用既有区间。
每批输出各缓冲的一个连续变更包络，`null` 表示无需上传。
WebGL 和 WebGPU 直接消费相同契约；新建或扩容 GPU 存储时完整初始化。
`UploadTracker`、CPU 镜像与逐 float 差异扫描全部删除。

数据空间填充的路径/样式不变时，在路径哈希前直接复用顶点段，
不再为了确认缓存命中而重新遍历全部点。

## 验证

原语准备现在独立为 `rendering/primitives/preparation`：编排器只冻结帧坐标并按顺序分派，
形状实例、解析描边、网格/stencil 分别拥有缓冲与复用记录。三者通过同一有序队列提交，
只合并相邻且缓冲连续的 draw；数据填充保留独立范围，跨类型绘制前提交待处理 stencil。
旧 `impl/prepare.ts` 已删除，后端和测试统一使用模块入口。

- 四种线型在窗口内滚动、价格缩放时保持路径与填充身份，GPU 变更区间全部为 null。
- 跨窗口、更新数据、切换坐标空间和释放缓存会正确失效。
- 描边覆盖实线、虚线、miter、半透明、闭合路径及非解析后端。
- 混合填充不会混用坐标；局部原点覆盖大坐标和亚分价差精度。
- 上传覆盖保留前后段、中间写入、GPU 重分配与原语列表容器复用。

浏览器基准只能证明对应受控场景的结果，不能替代完整应用交互 trace。
