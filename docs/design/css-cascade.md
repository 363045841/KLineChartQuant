# 共享控件与业务外观的 CSS 层叠规则

共享按钮及输入控件的默认外观保持无层（普通作者声明），业务组件的局部外观也是普通声明：两者按「特异性 → 出现顺序」比较，不使用 `@layer`。共享 primitive 只使用组件自己的类（编译后为 `.class[data-v-xxx]`）；业务覆盖必须让选择器更具体（加上所属容器的类，或从父组件用 `:deep()` 命中），不能依赖外部样式表的加载顺序。

宿主页面的全局 reset 必须是零特异性选择器：

```css
:where(*, *::before, *::after) {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}
```

`:where()` 不贡献特异性，任何组件类都能压过 reset，因此 reset 只归零 UA 默认值，不会清掉控件自己的 padding、边框和盒模型。禁止用 `*`、`button`、`input` 等带特异性的选择器做全局 reset：这些声明会污染共享控件（按钮失去 padding、Footer 下划线与文字宽度不一致、下拉触发器丢失边框），在旧方案里它们还会整体压过 `@layer kline-primitives`，因为无层声明优先于任何层。

作用域仍由 Vue scoped 样式保证。新增共享默认样式沿用单类选择器；业务组件只需要显式声明自己覆盖的属性，不使用 `!important` 提权。

产品验收在真实源码和 tarball 页面中反转已加载样式表的顺序，再逐像素比较完整工作台截图；正常顺序的源码与打包页面也继续做截图对比。验收覆盖自选列表按钮、Agent 模型菜单和输入框。比较只忽略视口边缘圆角抗锯齿在 ±1 色阶内的抖动：Chromium 对同一构建重复加载也会出现这种单像素噪声，任何成片或更大色差的差异仍然失败。
