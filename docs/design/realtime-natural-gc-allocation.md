# 实时更新的自然 GC 与临时分配

复测基准为真实 Binance BTCUSDT 1min，只启用一个默认参数 PVP。采样阶段不调用 collectGarbage，连续记录两分钟的主线程堆、Renderer 进程内存、V8 GC 事件，以及包含已回收对象的分配采样；结束后才强制 GC 做诊断对照。累计采样分配不是常驻内存，不与进程工作集相加。

首轮主线程已用堆约 45–61MiB，自然 GC 将容量从约 80MiB 缩到约 50MiB；Renderer 工作集约 509→321MiB，之后回升至约 386MiB。末尾强制 GC 后堆约 43MiB、工作集约 349MiB。本轮没有复现 700–800MB 长期不回落，不能把用户观察直接认定为 GC 不执行。

采样发现未来时间轴扫描反复读取仓库拓扑。只读 Map 代理在每次属性访问时执行 value.bind(target)，因此每一槽的多级 get 都创建临时函数；时间轴的槽位时间查询在未来槽位还重复查找同一 Buffer。仅该调用链的前几项累计采样分配便达数十 MiB。

修复把绑定方法的所有权放回拓扑快照：同一快照只在首次读取某方法时绑定，缓存随快照一起回收，不建立跨快照的全局缓存。时间轴单点查询只查一次活动 Buffer；后续该查询已收敛到帧坐标服务，不再读取仓库拓扑。

初始约 600 根行情的两次两分钟采样均记录 313 次动画帧。累计主线程采样分配约 332.6→293.6MiB；时间轴子调用树约 70.6→27.1MiB（约减少 62%），代理 get 自分配约 25.4MiB→0。主线程 MajorGC 记录 16→10 次、事件合计约 151.8→90.0ms；这是跨轮采样观测，不能据此保证 GC 次数或停顿上限。该阶段尚未修改会话范围与游标，收益只归因于仓库读取路径。

该修改减少已定位的实时临时分配，不控制浏览器 GC，也不保证标签页进程内存固定回落到某个数值。是否解决高位驻留，必须依据自然 GC 下的复测与用户原始场景对照。

另一个断点在有状态会话与 Core 计算范围的接缝：Core 按依赖扩大后的范围始终从 0 开始，会话据此认为每 tick 都发生历史修正，重建主运行态与全部 Request 运行态。会话已有上次输入快照，应使用 firstChangedBar 比较实际行情来证明末根回滚与追加是否安全；宿主范围继续用于无状态计算。真实历史前插、历史修正、参数和品种变化仍重建。跨周期历史修正同样撤销尾部复用，避免重置后从旧尾部位置开始运行。原生与 QuickJS 后端均验证累计状态输出与全量一致，并检查仅在真实历史变化时重复初始化。

执行循环退出后的游标原本停在开区间终点，导致常规检查点的 __count 多一根。同 bar 的递推序列可能未撤销末根 memo。本轮把两后端执行完成后的游标停在最后已执行的 bar；尾部追加仍从旧末根回滚位置重放，避免跳过旧末根。两后端用 EMA 验证末根更新与全量一致，用绘图验证追加后的对象数与差量输出。

用户确认其读数来自 Chrome 任务管理器，触发方式是加载更多历史。后续基准因此扩展为经图表原生 ensureDataRange 与真实拖动触发 40 轮历史分页，再保留实时更新观察自然回收。热更新中断过的历史测试仅作定位材料，不纳入完整 A/B 收益。

普通脚本顶层可变绑定没有检查点协议，仍须完整重放；编译产物显式携带 replayOnUpdate，将其与支持回滚的 TA、绘图和有状态库区分。库存在顶层可变状态时，只有显式向 defineLibrary 注册检查点才能复用。行情截断一律重建。这样恢复 PVP 增量时不会把普通累计变量误当成可回滚状态。

稳定的长历史测试完成 36 轮分页后，后续真实行情请求返回 504 并触发等待超时。因此未获得完整历史加载后的 A/B，不宣称 700–800MB 已稳定降到 400MB。该网络中断与此前 HMR 中断样本均不用于计算最终内存收益。
