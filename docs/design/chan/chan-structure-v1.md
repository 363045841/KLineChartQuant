# 缠论结构模块 v1

## 为什么做

订单流与成交量分布的单条件验证在 15m、4h、日线三个尺度上都被证伪（毛利约等于成本门槛）。
下一步要靠「位置 + 结构事件」的组合，结构事件需要一个可复现的实现。

## 为什么不直接引入 chan.py

OverMind 的评估结论（`docs/缠论流派评估与接入建议.md`）已论证：

1. 不建议把 chan.py 当运行时依赖：公开版缺策略层，`CChan` 是单体类且直接持有 K 线列表，无适配层。
2. 5300 行里大头是绘图、数据源、配置与缓存，算法核心（包含处理、分型、笔、中枢）体量有限。
3. 建议自研精简实现，把 chan.py 作为**对照测试的 oracle**。

本模块按这条结论落地：只做算法核心，不接数据源、不做绘图。

## 流派选择

对齐评估文档的推荐：**严格笔 + 段内中枢 + 固定周期近似级别**。

| 分歧点 | 本实现取值 | 理由 |
| --- | --- | --- |
| 包含处理 | 按已有方向取同侧极值；方向未定时取并集 | 无前序方向时不预设上下，避免第一根就引入偏差 |
| 分型 | 三根合并柱，顶/底需高与低同时满足 | 与严格笔口径一致 |
| 笔 | 顶底交替、至少隔 4 根合并柱、同类型取更极端 | 减少噪音笔，保证端点单调 |
| 中枢 | 连续三笔区间交集，重叠则延伸 | 不做真递归级别，用固定周期近似 |
| 线段 | v1 不实现 | 线段依赖特征序列与破坏判定，先验证笔与中枢够不够用 |

## 边界

- 模块只输出结构事实：合并柱、分型、笔、中枢。**不含任何交易判定**。
- 依据 issue #15 的分工：结构事实供 Skill 解读，判定与出单在 playbook 层。
- 不读原始 K 线之外的数据，不涉及期货/现货口径差异。

## 契约

见 `packages/core/src/features/chan/types.ts`。入口为子路径导出 `@363045841yyt/klinechart-core/chan`。

## 验证

`packages/core/src/features/chan/__tests__/chan.test.ts`，11 例，覆盖包含处理的三种方向、分型识别、成笔与不成笔、同类型合并、中枢形成与不形成、空输入。

## 已知缺口

1. 线段与走势类型未实现，中枢只用笔级。
2. 未做因果性验证：当前实现对整段 K 线一次算完，实盘需要增量更新与「已确认」标记。
3. 未与 chan.py 做对照测试（评估文档要求的 oracle 对齐），需要导出同一段 K 线比对笔与中枢序列。
